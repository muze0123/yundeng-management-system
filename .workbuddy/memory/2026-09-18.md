## 技术要点 / 教训
- `billing-invoice.js` 的 `scripts[]` 是 JSON 字符串数组。编辑必须走「JSON 往返编解码」：先正则剥掉缩进与尾逗号再 `json.loads`，改完 `json.dumps(ensure_ascii=False)` 写回并还原缩进/逗号，否则转义（`\"`、`\\n`）会损坏整个模块。
- 该模块 `before[]` 在运行时被硬置空（约 L2352 处 `before = []`），故 line 23 的 before 补丁层是**死代码**，改状态词只需改 `scripts[0]`（base view）。
- 改 Prototype 模块 JS/CSS 后**必须**同步 bump `Prototype/app-shell.js` 的 MODULE_VERSION 与 `index.html` 的两处 `?v=`，否则用户端命中浏览器缓存。

## 经验（可复用）
- 大文档批量改写用「精确子串 + 期望命中数断言」的脚本一次跑完，命中数不符就整体中止不写入；比逐条 Edit 更安全，且能直接产出残留报告。
- 表格行删除务必只匹配**行内容 + 行尾换行**；Markdown 表格行是整行删除，而 JSON 字符串内的 `\n` 是字面反斜杠-n，两者不能混用同一套转义写法（本轮踩过一次）。
