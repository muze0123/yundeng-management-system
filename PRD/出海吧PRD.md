## 〇、交付物对照（同名前缀易混淆，务必区分）

「出海吧」共有 4 个文件，名字都带「出海吧」，但**性质与用途完全不同**：

| 文件 | 性质 | 用途 / 特征 |
|---|---|---|
| `Prototype/modules/overseas-nav.js` | 后台模块（唯一维护端） | 云登后台一级菜单「出海吧」的管理界面：双 Tab（网站管理 / 类型管理）+ 列表 + 弹窗 + 拖拽排序；**唯一的写入端**，数据写 localStorage |
| `Prototype/出海吧.html` | 旧文件名兼容入口 | 约 0.5KB 的重定向页，`location.replace` 跳到 `index.html?page=overseas-nav`；**不是**对外页面 |
| `exports/出海吧-独立页面.html` | **对外导航站页面** | 面向访客的单文件自包含页面（手写维护，**不经** `export-standalone.py` 导出）：左侧类型导航 + 精选推荐 + 网站卡片宫格 + 页脚；只读 localStorage。细则见 `PRD/出海吧独立页PRD.md` |
| `exports/出海吧-独立版.html` | 后台模块的单文件快照 | `python3 scripts/export-standalone.py overseas-nav` 的产物：把版式框架 + 本模块 + 内联 Tailwind/lucide 打成一个离线可打开的文件，保留后台顶栏/侧栏，供**分享与评审**用；**不是**对外页面 |

> 两个 `exports/` 文件的区别一句话概括：**「独立页面」是发给用户看的导航站；「独立版」是发给同事看后台管理界面。**

## 一、背景与目标

为出海用户提供一个「出海工具导航站」：独立 HTML 页面按网站类型分组展示工具网站卡片（参考 partnershare.cn 布局）。云登后台新增一级菜单「出海吧」，用于维护该导航站的网站与网站类型。**原型阶段无真实后端，两页面通过 localStorage 同键位打通**：后台改动实时写入，独立页面实时读取（`storage` 事件跨标签联动）。

## 二、数据契约（两页面共享，唯一事实来源）

- localStorage 键：`yundeng_overseas_nav_v1`
- 结构：
  ```json
  {
    "version": 1,
    "types": [ { "id": "t1", "name": "AI 工具", "icon": "" } ],
    "sites":  [ { "id": "s1", "name": "IPFoxy", "url": "https://...", "intro": "...",
                  "typeId": "t1", "featured": true, "icon": "" } ]
  }
  ```
- `types` 数组顺序 = 类型展示顺序；`sites` 数组顺序 = 网站全局排序（组内按数组序）。
- `icon` 为空 → 按网址域名自动匹配 favicon（`https://favicon.im/{域名}?larger=true`，加载失败降级为首字母色块头像）；`icon` 为 data URL → 使用上传图。
- 独立页面读取失败 / 键不存在 / file:// 下受限时，回退到内置种子数据（种子结构与契约一致）。
- 后台删除类型时：若类型下仍有网站，**禁止删除**并提示「请先移除或转移该类型下的 N 个网站」。

## 三、独立页面（exports/出海吧-独立页面.html）

> **完整 PRD 已拆分为独立文档：`PRD/出海吧独立页PRD.md`**。页面结构、导航 / 分组 / 卡片、页脚、回到顶部、交互状态与验收的细则以该文档为准。本节只保留**与后台模块的耦合口径**，避免同一份页面存在两个事实来源。

- **定位**：面向访客的「出海工具导航站」（参考 `partnershare.cn`），单文件自包含、可独立分发；**只读**（不写入 localStorage）。
- **数据来源**：同键位 `yundeng_overseas_nav_v1`（见第二章契约）；读取失败/键不存在时回退内置种子；监听 `storage` 事件实现跨标签即时联动。
- **与后台模块的耦合口径**（改动后台时需同步检查独立页）：
  - `types` 数组顺序 = 独立页左侧导航顺序 + 内容分组顺序；
  - `sites` 数组顺序 = 各分组内卡片顺序；
  - `featured` = 独立页「精选推荐」分组的入选条件与卡片「荐」角标；
  - `icon` = 独立页图标（上传图优先，未上传按域名匹配 favicon，失败降级首字母色块）；
  - `typeId` = 卡片归属分组（孤立 `typeId` 渲染为「未分类」）。
- **页面侧细则**：见 `PRD/出海吧独立页PRD.md` 第四~十一章。

## 四、后台模块（overseas-nav）

### 4.1 页面结构
一级 Tab 双页签（design.md §5.0：**下划线式主 Tab**，非分段控件；无页面标题/副标题）：
- **网站管理**（默认）：筛选区（搜索 + 网站类型 + 是否精选 + 查询/重置）+ 网站列表 + 「添加网站」。
- **类型管理**：类型列表 + 「添加类型」。

筛选条件归属「网站管理」页签，切到「类型管理」时随页签隐藏；Tab 与内容之间由 Tab 容器下边框（line-light）承担分割线。

**区块结构**（design.md §5.0「无筛选条件页签的区块合并」）：

- 区块 1 = 一级 Tab；「网站管理」页签下同区块承载筛选区，其网站列表为**独立的区块 2** → 该页签为两区块。
- 「类型管理」页签**不含任何筛选条件**，其类型列表**并入区块 1**：切到该页签时整页只呈现**一个区块**，不再出现「只剩一条页签的空区块 + 独立列表卡片」的两段式结构。
- 并入面板自身不承载卡片样式（无白底 / 圆角 / 内边距），列表内间距全部来自区块 1 的内边距；页签与列表之间由页签的 20px 下间距承担，避免卡片套卡片。
- 判断依据是「该页签是否具备筛选条件」这一静态结构事实，与用户当前是否填写筛选值无关。

### 4.2 网站管理
- **筛选条件**（草稿态，点「查询」统一提交，design.md §5.4）：
  - 搜索：按网站名称 / 网址 / 简介模糊匹配（不即时生效，清空按钮仅清空输入并保持焦点）。
  - 网站类型：下拉单选，选项 = 「全部类型」+ 类型管理维护的类型；新增/编辑/删除类型后选项自动同步。
  - 是否精选：下拉单选，选项 = 「全部」/「是（精选推荐）」/「否」；用于按精选状态过滤列表。
  - 查询 / 重置：三项条件为**与**关系叠加生效；重置清空三项条件并恢复默认结果；筛选生效时列表**禁止拖拽排序**（避免与全量顺序错位），并显示「共 N 条（筛选自 M 条）」。
- **列表列**：排序（拖拽手柄）/ 图标+名称 / 网址 / 类型 / 简介 / 精选 / 操作（编辑、删除）。
  - 「网站」列只展示图标与名称，**不再重复展示精选标签**；精选状态由独立「精选」列承担。
  - 「简介」列：单行截断展示；鼠标移入或键盘聚焦时，在行下方展示**完整简介气泡**（fixed 定位、宽度上限 280px、超长自动换行、不被表格横向滚动容器裁切；移出 / 失焦 / `Escape` / 滚动 / 窗口尺寸变化时收起）。不写原生 `title`，避免与自定义气泡叠加出现双重提示。
  - 「精选」列：**星标按钮**（Lucide `star`）。实心橙色 = 已推荐，灰色描边 = 未推荐；**点击即设为推荐，再次点击取消推荐**，即时写入 localStorage、toast 反馈，并同步 `aria-pressed` 与按钮提示文案（「设为推荐」/「取消推荐」）。
- **拖拽排序**：行手柄可拖拽换位（HTML5 DnD），落位即写 localStorage，全量顺序生效。
- **添加/编辑网站（Modal，760px，design.md §5.6）**，字段：
  - 弹窗规格：宽度 760px、内容区 padding 32px 24px、字段区块在内容区居中（标签 90px 右对齐并带中文冒号「：」，控件 400×30px）、底部操作区 line-light 分隔线 + 纯文字按钮居右。
  - 网站图标（选填）：① 输入网址后自动匹配 favicon 并预览；② 点击「上传图标」选本地图片转 data URL（≤200KB）；可清除回退自动匹配。
  - 网站名称（必填，≤30 字，计数器位于输入框内右侧）；网站网址（必填，URL 格式校验）；网站简介（必填，多行文本域高度 **60px**，≤100 字，**计数器位于文本域内右下角**）；网站类型（必填，下拉单选，选项=类型管理维护的类型，**未选择时占位文案「请选择类型」以占位灰 `#9DA2AC` 显示，选中真实类型后恢复正文色**）；设为精选推荐（Toggle）。
  - 编辑时同弹窗回填；新增成功后清空筛选条件以保证新数据可见。
- **删除**：confirm 类型 Dialog（§5.8：600×250、ICO `?`、底部无分隔线、按钮 padding 6px 20px），确认后移除并写 localStorage。

### 4.3 类型管理
- **区块归属**：类型列表位于区块 1（页签区块）内部，页面只呈现一个区块（见 §4.1）；列表标题行下间距与「网站列表」统一为 12px。
- **列表列**：排序（拖拽手柄）/ 类型 ico / 类型名称 / 网站数量 / 操作（编辑、删除）。
- **添加/编辑类型（Modal，760px，规格同 §5.6）**：类型 ico（选填，同自动匹配/上传逻辑，自动匹配源为类型名首字）、类型名称（必填，≤12 字，计数器）。
- 删除约束见第二章；被引用中的类型在网站表单下拉与筛选下拉中照常可选。

### 4.4 状态与反馈
- 所有写操作 toast 反馈；空搜索结果显示空态文案。
- 聚焦态遵循 design.md §5.13 单一指示铁律（`.on-module` 作用域）。

## 五、验收要点

> 说明：本章同时保留原有的**页面侧**条目（第 2、3、4、6、12、12.1、13、14 条）作为跨页提醒；这些条目在 `PRD/出海吧独立页PRD.md` §十一另有完整版本，两者表述冲突时**以独立页 PRD 为准**。

1. 后台添加/编辑/删除/排序/精选开关后，独立页面刷新或跨标签即时反映。
2. 精选分组 chips 过滤、卡片 hover 全显简介、点击新开标签页均可用。
3. 侧栏收起/展开、滚动定位与高亮联动正常。
4. 图标：无上传时 favicon 自动匹配，失败降级首字母头像；上传后优先使用上传图。
5. 类型删除保护：含网站时不可删除。
6. file:// 直开独立页面不白屏（种子数据回退）。
7. 后台双页签为下划线式主 Tab；切到「类型管理」时筛选区隐藏，切回后恢复。
8. 筛选区「草稿态 + 查询/重置」行为正确（不即时过滤、重置恢复默认）；关键词、网站类型、是否精选三项可叠加（AND）。
9. 列表「网站」列不含精选标签，精选状态仅在「精选」列体现（星标按钮）；筛选生效时拖拽手柄禁用。
9.1 简介列鼠标移入/键盘聚焦展示完整简介气泡，移出/失焦/Esc/滚动后收起，且不被表格滚动容器裁切。
9.2 「精选」列星标点击可设为推荐、再次点击取消推荐，状态即时持久化并同步 aria-pressed。
9.3 筛选区「是否精选」下拉（全部 / 是（精选推荐）/ 否）可按精选状态过滤；与「搜索」「网站类型」三条件 AND 叠加生效，重置后三项全部清空并恢复全量 28 条。
9.4 添加/编辑网站弹窗中「网站简介」文本域高度为 60px（计数器仍在文本域内右下角、文字不与其重叠）；「网站类型」下拉未选择时占位文案「请选择类型」为占位灰（`#9DA2AC`），选中真实类型后恢复正文色，编辑回填已有类型时不为灰色。
10. 弹窗规格符合 design.md §5.6（760px、内容区 32px 24px、标签 90px 带中文冒号、控件 400×30px、字段区块居中、底部纯文字按钮居右）；删除确认符合 §5.8（600×250、无底部分隔线）。
11. 顶栏与页脚的平台名称「出海吧」均为纯标题黑（无彩色片段）。
12. 独立页页脚符合 §3.5：白色背景卡片、左右与底部各内缩 20px、8px 圆角、四边描边；桌面三列 / 移动端单列；三列内容（品牌+定位语 / 产品链接 / 联系方式图标）齐全；联系方式三个图标**鼠标移入**分别展开邮箱地址、微信二维码、客服二维码浮层，移出即收起，浮层不被内容区裁切；键盘聚焦图标同样可展开（`focus-within`）；法务行含公司名、公安备案徽标（内嵌 data URI、位于「浙公安网备」之前）与两个备案号，协议链接地址正确；页脚正文文字对比度 ≥ 4.5:1。
12.1 页脚二维码为占位槽（132×132 虚线框 + 说明文案），源码留有 `TODO` 替换注释；替换为真实二维码图片后无需改动其他样式。
13. 页脚样式符合参考图（PartnerShare）：栏目标题为浅灰 `#3A3F4A`；联系方式图标为 36×36 深色圆角方块（白图标，hover 切主色）；栅格比例 `2fr / 1fr / auto`。
14. 回到顶部按钮符合 §3.6：固定于视口右下角 24px、40×40 圆形、`aria-label` 与提示语「回到顶部」正确；hover/聚焦显示提示语、移出收起；**真实点击后线性滚动回顶部**（滚动的中间采样点符合线性比例，非缓动曲线），最终 `scrollTop = 0`；按钮点击区不被遮挡。
15. 区块结构符合 design.md §5.0：切到「类型管理」时整页只呈现**一个区块**（类型列表面板位于页签区块内部，且自身无白底/圆角/内边距，不出现卡片套卡片）；切到「网站管理」时为两个区块（页签+筛选 / 网站列表）；类型列表标题行下间距与网站列表一致。

## 六、开放问题

- **文本域计数器位置偏离 design.md §5.9**：design.md §5.9 规定多行文本域计数器位于「控件外下方、右对齐」；本项目按用户明确要求改为「文本域内右下角」（文本域高 60px，底部预留 22px 内边距避免文字与计数器重叠）。如需与其他模块统一，需同步修改 design.md §5.9 或本模块回退到外侧口径。
- 后续接真实后端时，localStorage 契约需替换为接口（字段结构可直接映射）。
- 独立页面若需公开部署，建议将「出海吧」数据改为只读快照导出（当前方案已预留 version 字段）。
