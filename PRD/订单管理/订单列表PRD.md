## 1. 需求概述

### 1.1 页面定位

订单列表是云登后台订单管理下的跨业务订单总览页面，面向运营、客服、财务和具备订单权限的管理员，集中检索订单主记录并判断订单所处的支付、履约和售后状态。本页承接用户、团队、企业和支付链路产生的订单，输出详情查看、订单处理和导出任务；套餐规格、套餐权益和套餐续费专属分析由“套餐订单”页面承接。本页不修改商品定义、不编辑套餐配置、不替代支付渠道后台。

### 1.2 背景与问题

用户、团队、企业和资源业务可能产生不同类型的订单。若各业务入口分别查看，运营人员无法用统一订单号、购买主体、金额、支付结果和履约状态定位问题；支付成功但资源尚未生效、退款处理中、补单等异常也缺少同一处可追溯的处理入口。

本需求建立一个以订单主实体为中心的列表页：用统一字段承载跨业务订单，用独立状态字段区分支付与履约，用详情抽屉呈现业务扩展信息，并把取消、退款、补单和状态处理纳入权限与审计闭环。

### 1.3 一句话目标与成功指标

**一句话目标：**让有权限的后台人员在一个页面内按订单主字段定位目标订单，查看完整事实链，并在服务端允许的状态下完成可审计的订单处理。

|指标|定义|目标|数据来源|
|---|---|---|---|
|查询完成率|点击查询后成功返回列表的次数 / 查询提交次数|≥99%（排除鉴权失败）|订单列表查询日志|
|详情定位时长|从进入页面到打开目标订单详情的中位时长|≤30 秒|页面行为埋点|
|状态处理成功率|服务端确认成功的处理操作 / 处理提交次数|≥99%|订单操作日志|
|导出审计覆盖率|带查询快照和操作者信息的导出任务 / 全部导出任务|100%|任务与审计日志|

### 1.4 用户、角色与任务

|角色|任务|读取范围|可写操作|
|---|---|---|---|
|运营管理员|定位订单、处理支付/履约异常|授权团队/企业范围|详情、取消、状态处理、补单、导出|
|客服|查看订单并协助售后|授权客服范围|详情、发起退款（需退款权限）、状态处理|
|财务|核对支付、退款与金额|授权财务范围|详情、退款、导出|
|只读审计员|查询与追溯|授权范围|仅详情、导出（导出权限单独校验）|

前端隐藏或置灰只用于体验，所有列表、详情、导出和写操作接口必须再次进行服务端鉴权。无订单查看权限时不返回订单数据。

|本期包含|本期不包含|后续依赖|
|---|---|---|

### 1.6 前置约束与假设

|类型|约束/假设|影响|
|---|---|---|
|业务规则|订单列表的“订单类型”由订单服务提供；原型使用代理服务、API/RPA 服务、环境增购、增值服务作为示例类型。|真实接入时仅替换枚举和商品文案，不改变列表结构。|
|金额|列表金额展示订单应付总额，人民币保留两位小数；退款金额在详情中单独展示。|服务端负责精度、币种和舍入。|
|时间|页面统一使用 `Asia/Shanghai`；订单号、金额和时间戳使用等宽字体。|跨时区用户需由服务端返回已转换显示值。|
|隐私|手机号、邮箱和支付流水默认脱敏；详情中的临时明文查看需独立权限并记录审计。|原型只展示脱敏值。|
|异步|导出和补单可能异步；提交后返回任务号，列表不提前伪造成功。|页面提示“任务已提交”，最终结果由任务中心承接。|
|补单|补单是受控的人工补录动作，只允许具备权限且有业务依据的管理员提交；不能伪造支付渠道成功回调。|补单后订单进入“已支付”或“处理中”必须由服务端规则确认。|

## 2. 信息架构、入口与流程

### 2.1 入口与路由

|入口|路由/文件|默认状态|
|---|---|---|
|侧边栏“订单管理 / 订单列表”|`Prototype/订单列表.html`|状态为“全部”，按创建时间倒序|
|系统框架订单列表路由|`order-list` → `订单列表.html`|保持公共侧栏和面包屑上下文|
|订单通知/待办深链|`订单列表.html?order_id=<订单号>`|打开详情抽屉；无权限显示无权限态|
|导出完成通知|任务中心下载任务|保留原查询快照，不改变当前筛选|

### 2.2 主流程

```text
进入页面 → 服务端鉴权 → 加载默认订单列表
 → 选择状态/筛选条件 → 查询（第 1 页）
 → 点击订单号/详情 → 打开详情抽屉
 → 选择允许的取消/退款/状态处理/补单操作
 → 前端校验 → 确认 → 服务端鉴权、幂等、状态校验
 → 成功：刷新当前查询并记录审计；失败：保留上下文并提示原因
```

### 2.3 关键场景

|编号|优先级|场景|成功结果|异常/恢复|
|---|---|---|---|---|
|S-01|P0|运营人员按订单号或购买主体查询订单|列表返回匹配结果并回到第 1 页|无结果展示“未搜索到相关订单”，保留筛选条件。|
|S-02|P0|客服从异常状态打开订单详情|抽屉展示支付、履约、退款和日志事实|订单已被其他人处理时，服务端拒绝旧版本操作，提示刷新。|
|S-03|P0|具备权限的管理员取消待支付订单|确认后订单变为“已取消”，列表自动刷新|仅允许待支付/支付失败等服务端允许状态；重复提交幂等。|
|S-04|P0|财务发起退款|输入退款金额和原因，确认后进入“退款中”|金额超过可退余额、重复退款或渠道异常时保留抽屉并提示原因。|
|S-05|P0|运营人员提交补单|填写依据、金额和备注，服务端生成补单结果|缺少依据或重复补单时阻止提交；异步结果可在任务中心追踪。|
|S-06|P1|只读审计员导出当前筛选结果|创建带查询快照的异步导出任务|无导出权限、任务失败或文件过期时给出明确提示。|
|S-07|P0|无订单数据/网络异常/无权限|页面展示对应空态、错误态或无权限态|允许在不丢失筛选条件的情况下重试。|

## 3. 数据模型与状态机

### 3.1 订单主字段

|字段|类型|展示规则|是否列表展示|
|---|---|---|---|
|order_id|字符串|平台订单号，完整值可复制|是|
|order_type|枚举|代理服务、API/RPA 服务、环境增购、增值服务等|是|
|buyer|对象|购买主体名称 + 主体类型（用户/团队/企业）|是|
|service_item|对象|业务商品/服务名称；不展示套餐权益拆解|是|
|quantity|整数|数量或计费单位数量|详情展示|
|payable_amount|金额|`¥0.00` 格式，等宽字体|是|
|payment_method|枚举|微信支付、支付宝、余额、人工补单等|是|
|payment_status|枚举|待支付、支付中、已支付、支付失败|详情/筛选|
|fulfillment_status|枚举|未开始、处理中、已完成、已暂停、已取消|详情/筛选|
|display_status|枚举|按状态优先级聚合后的页面 Badge|是|
|created_at|时间|`YYYY-MM-DD HH:mm:ss`|是|
|paid_at|时间|未支付显示“—”|详情|
|refund_amount|金额|累计已退款金额|详情|
|source|枚举|用户端、运营补单、API 等|详情|
|updated_at|时间|最近一次服务端状态更新时间|详情/日志|

### 3.2 页面展示状态

|展示状态|进入条件|允许的页面操作|语义色|
|---|---|---|---|
|待支付|订单已创建，未收到支付结果|取消、详情、导出|warning|
|支付中|已发起支付，等待渠道结果|详情、刷新|info|
|已支付|支付成功且未进入终态|详情、状态处理、退款（有余额时）、导出|success|
|处理中|支付成功，资源/服务尚未完成|详情、状态处理、退款（按服务规则）|info|
|已完成|履约成功|详情、导出|success|
|已取消|订单取消成功|详情、导出|终态灰|
|退款中|退款请求已提交，渠道尚未最终确认|详情、刷新|warning|
|已退款|退款全部完成|详情、导出|终态灰|
|支付失败|支付渠道明确失败|详情、取消、补单（有权限）|danger|

页面展示状态由服务端计算，前端不可通过点击直接篡改。支付状态和履约状态在详情抽屉中分开呈现，避免“已支付”被误读为“服务已完成”。

### 3.3 操作前置条件

|操作|前置条件|确认文案/输入|成功后|
|---|---|---|---|
|取消订单|服务端允许取消，且订单未完成退款|“确认取消该订单吗？取消后不可恢复。”|刷新列表，Toast“订单已取消”|
|发起退款|存在可退余额，具备退款权限|退款金额、退款原因必填；金额不得大于可退余额|进入“退款中”，Toast“退款申请已提交”|
|状态处理|具备处理权限，目标状态符合状态机|选择目标状态 + 处理说明|刷新列表，Toast“订单状态已更新”|
|补单|具备补单权限，填写业务依据、金额和备注|确认“提交补单申请”；不代表支付渠道成功|创建补单任务，Toast“补单任务已提交”|
|导出|具备导出权限|确认当前筛选条件与字段范围|创建下载任务，Toast“导出任务已提交，请前往任务中心查看”|

## 4. 页面与交互规格

### 4.1 页面布局

页面使用系统框架的 Sidebar + Header + Content 壳层。主内容区遵循设计系统“两区块”结构：上方筛选区、下方数据区；不单独设置页面标题卡片。数据区表格外层允许横向滚动，侧栏在平板宽度下折叠为 68px。

### 4.2 状态 Tab

Tab 顺序固定为：全部、待支付、支付中、已支付、处理中、已完成、已取消、退款中、已退款、支付失败。点击 Tab 立即更新状态条件但不自动发起写操作；点击“查询”后提交请求并回到第 1 页。选中态使用 `primary` 文字和底部 2px 指示线。

### 4.3 筛选区

|控件|默认值|规则|
|---|---|---|
|订单号/购买主体|空|支持订单号精确匹配；购买主体名称模糊匹配；最多 50 字。|
|订单类型|全部|单选；枚举由服务端返回。|
|支付状态|全部|待支付/支付中/已支付/支付失败。|
|履约状态|全部|未开始/处理中/已完成/已暂停/已取消。|
|创建时间|最近 30 天|开始时间不得晚于结束时间；最大查询跨度 730 天。|
|查询/重置|—|查询应用 AND 条件并回到第 1 页；重置恢复默认值。|

筛选项采用 `filter-flow` 流式布局，桌面控件基准宽度 400px；窄屏控件缩小并保持标签与输入框对齐。搜索框有内容时显示清空按钮，清空不自动查询。

### 4.4 数据区与表格

数据区标题为“订单列表”，右侧提供“刷新”“导出订单”“补单”按钮。指标卡展示：订单总数、待支付、处理中、退款中；数字使用等宽字体。表格字段顺序：订单号、购买主体、订单类型、业务商品、应付金额、支付方式、订单状态、创建时间、操作。表格行 hover 使用 `bg-hover`，订单号可点击打开详情抽屉。

列表每页默认 10 条，可选 10/20/50；分页器显示页码、条/页、跳页和总数。当前筛选结果为空时展示“未搜索到相关订单”；首次无数据展示“暂无订单数据”。

### 4.5 详情抽屉

抽屉宽度 800px，右侧滑入，遮罩点击关闭。标题显示订单号与当前状态。内容分为：订单摘要、购买主体、业务商品、支付信息、履约信息、退款记录、操作日志。敏感信息默认脱敏，订单号和支付流水支持复制并显示 Toast。抽屉底部按当前状态展示允许的操作按钮；不允许的操作不展示，不仅仅依赖前端禁用。

### 4.6 操作弹窗

取消、退款、状态处理、补单使用居中 Modal/Dialog：

- 取消：确认弹窗，无需额外字段。
- 退款：退款金额（必填，金额格式校验）、退款原因（必填，最多 200 字）。
- 状态处理：目标状态（必填）、处理说明（必填，最多 300 字）。
- 补单：购买主体、订单类型、业务商品、金额、业务依据、备注均须校验；提交后进入异步任务。

提交按钮在请求期间 loading 且不可重复点击；服务端失败时保留已填写内容并给出可行动原因。

### 4.7 导出

导出确认弹窗显示当前筛选摘要和预计字段：订单号、购买主体、订单类型、业务商品、应付金额、支付方式、订单状态、创建时间、支付时间、履约状态。导出绑定不可变查询快照、操作者、字段权限和过期时间；前端仅展示任务提交结果。

## 5. 权限、隐私与审计

权限点：`order.list.read`、`order.detail.read`、`order.cancel`、`order.refund`、`order.status.update`、`order.manual_create`、`order.export`。所有接口服务端鉴权，权限在页面停留期间变化时，下一次操作必须重新校验。

审计记录至少包含：操作者、角色、订单号、操作类型、操作前状态、操作后状态、金额变化、原因/备注、请求时间、结果、失败原因、幂等键和查询快照 ID。手机号、邮箱、支付流水等敏感字段不得写入前端埋点原文。

## 6. API 与异步约定

|接口能力|请求要点|返回/失败|
|---|---|---|
|查询订单列表|筛选条件、页码、页大小、查询快照 ID|返回列表、总数、权限裁剪后的字段；超时可重试。|
|查询订单详情|订单号、数据权限上下文|返回主字段、扩展字段、日志；无权时返回明确权限错误。|
|取消/退款/状态处理|订单号、目标状态/金额、原因、幂等键、版本号|成功返回最新订单版本；版本冲突返回“订单已被更新，请刷新”。|
|补单|订单草稿字段、业务依据、幂等键|返回任务号和处理中状态，不提前宣告支付成功。|
|创建导出任务|查询快照 ID、字段白名单、幂等键|返回任务号；任务中心提供最终文件和失败原因。|

前端查询请求使用 requestId 防竞态，旧响应不得覆盖新筛选结果；写操作使用按钮级防重复和服务端幂等键。

|T-06|补单提交|补单任务已提交|
|T-07|导出提交|导出任务已提交，请前往任务中心查看|
|T-08|复制成功|订单号已复制|
|T-09|可恢复失败|操作失败，请检查原因后重试|

成功提示必须在服务端成功确认后展示；异步操作只展示“已提交/处理中”，不提前显示终态。

## 8. 交互标注清单

原型中的交互标注从 1 开始连续编号，覆盖：状态 Tab、组合筛选、查询/重置、指标卡、订单号与详情抽屉、批量选择/导出、补单、取消、退款、状态处理、敏感字段与异步结果。标注只解释业务规则，不为公共侧栏、通知和账号菜单编号。

## 9. 非功能与验收标准

### 9.1 非功能要求

- 首屏列表在正常网络下 2 秒内展示加载态或数据；查询请求超时不清空当前结果。
- 订单号、金额、时间戳使用等宽字体；表格宽度超出视口时只在表格容器横向滚动。
- 所有按钮、输入框、弹窗具备键盘焦点和可读 aria-label；颜色不是唯一状态表达。
- 页面不依赖本地 CSS/JS/图片，双击 HTML 可预览；仅使用 Tailwind、Lucide CDN 和原生 JavaScript。

### 9.2 验收清单

- [ ] 默认进入页面显示全部订单且按创建时间倒序。
- [ ] 状态 Tab、五类筛选条件、查询和重置均真实生效并回到第 1 页。
- [ ] 订单列表至少展示 8 条 mock 数据，覆盖待支付、处理中、已完成、退款中、已取消、支付失败等状态。
- [ ] 订单号打开详情抽屉；抽屉遮罩、关闭、复制和状态相关按钮可用。
- [ ] 取消、退款、状态处理和补单均有字段校验、确认、防重复提交、成功/失败反馈。
- [ ] 导出展示筛选快照并提交异步任务提示。
- [ ] 分页支持页码、每页 10/20/50 条和跳页；表格在窄屏横向滚动。
- [ ] 无结果、加载中、错误、无权限文案明确；不泄露敏感数据。
- [ ] 交互标注可显隐，弹窗/抽屉打开时页面标注自动切换为作用域内标注。
- [ ] 系统框架、侧栏交互和 index 导航均可进入 `订单列表.html`，当前菜单高亮唯一。
