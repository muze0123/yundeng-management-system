### 1.1 背景与问题

- 当前流程：`运营人员/客服` 在`用户咨询佣金金额、提现门槛或质疑漏结算`时，通过`分别查询订单管理、用户提现、套餐订单等多个列表`拼凑判断，缺少以「用户」为中心的返佣聚合视图。
- 已知问题：① 逐笔返佣的来源订单无法从用户维度一次性追溯，平均定位耗时高；② 冻结佣金与解冻时间分散在结算侧，客服无法当场答复「为什么还不能提现」；③ 返佣比例与提现门槛属于全局资金参数，缺少集中入口，变更无审计依据。
- 根因假设：返佣数据在数据模型上以「订单」与「提现流水」为主实体存储，缺少面向运营的**用户维度聚合与下钻链路**，也缺少参数配置的规范化入口。
- 本需求的解法：建立「返佣汇总 → 四类明细」的下钻结构（汇总行内嵌「明细」入口并按用户预置筛选），并集中提供返佣比例与提现门槛的编辑能力及取值约束。

### 1.2 一句话目标与成功指标

**一句话目标：** 在**用户咨询或定期对账**场景下，让**运营与客服**以**「按用户搜索 → 汇总看总览 → 点明细定位来源订单」**的关键路径完成**返佣核对与答复**，同时将**误改资金参数的风险**控制在**仅限授权角色、且全部变更留痕**的阈值内。

| 指标 | 指标定义（分子/分母） | 基线 | 目标 | 统计周期 | 数据来源 | Owner |
|---|---|---|---|---|---|---|
| 核心结果指标 | 返佣类咨询从发起到关闭的平均处理时长 | 【待确认基线】 | 下降 ≥30% | 月 | 客服工单系统 | 【待填】 |
| 漏斗指标 | 进入返佣汇总后发生「明细」下钻的会话占比 | — | ≥40%（若显著偏低说明汇总信息不足） | 周 | 埋点 | 【待填】 |

### 3.2 编辑弹窗（返佣比例 / 提现设置）

**页面目的：** 在受约束的取值范围内修改单个返佣参数，并给出成功/失败反馈。
**呈现形态：** Modal（`.rm-modal`），遮罩铺满内容区。
**布局与滚动：** 头部（标题 + 关闭）→ 主体（字段行 + 错误行 + 提示行）→ 底部（取消 / 确定，右对齐）；主体超出时内部滚动。

```Plaintext
┌ Modal ────────────────────────────────┐
│ 编辑返佣比例                      [×] │
│ ───────────────────────────────────── │
│        海鸥：  [ 20 ]%                │
│        （错误行：常驻至修正）           │
│        返佣比例取值 0 ～ 100，…        │
│ ───────────────────────────────────── │
│                        [取消] [确定]  │
└───────────────────────────────────────┘
（金额类：字段前缀为 ￥，标签不带「（元）」）
```

### 5.3 业务规则清单

| 编号 | 规则 | 触发时机 | 优先级/冲突规则 | 实现责任 | 验证方式 |

| B-R01 | 汇总四列口径自洽：`累计佣金 = 可提现金额 + 冻结佣金 + 累计提现` | 数据聚合 | 以服务端聚合结果为准，前端不重算 | 后端 | 接口测试 + 对账脚本 |
| B-R02 | `返佣金额 = 订单支付金额 × 结算时返佣比例` | 结算 | 比例在结算时固化，不随参数调整回改 | 后端 | 单测 |
| B-R03 | 筛选条件之间为 **AND**；任一条件为空则不限制该维度 | 查询 | 空值不参与过滤 | 前后端一致 | E2E |
| B-R04 | 用户类筛选为「包含」匹配；邮箱与账户名忽略大小写 | 查询 | — | 前后端一致 | 单测 |
| B-R05 | 时间筛选按**日粒度闭区间**比较 | 查询 | 时区以服务端配置为准【待确认】 | 前后端一致 | 单测 |
| B-R06 | 查询 / 重置 / 排序 / 下钻后页码统一回到第 1 页 | 交互 | — | 前端 | E2E |

| B-R08 | 仅返佣汇总支持排序；默认 `累计佣金` 降序；同列点击切换方向，换列默认降序 | 交互 | 不可排序列：用户ID、手机号/邮箱/账户 | 前端 | E2E |
| B-R09 | 「明细」跳转须携带用户上下文：提现明细用「邀请用户ID」，其余用「邀请者=手机号」 | 下钻 | 有优先于无 | 前端 | E2E |
| B-R10 | 返佣设置保存前必须同时通过「取值区间」与「min < max 交叉约束」 | 保存 | 服务端最终判定，前端仅预校验 | 前后端 | 接口测试 |

### 5.4 并发、幂等与一致性

| 场景 | 风险 | 约束/方案 | 用户可见结果 |
|---|---|---|---|
| 连续点击「确定」保存设置 | 重复写入同一参数 | 前端提交中禁用按钮 + `Idempotency-Key`；服务端幂等 | 仅一次生效，提示一次 |
| 两名运营同时编辑同一参数 | 后写覆盖先写 | `version` 乐观锁；冲突返回最新快照与 `VERSION_CONFLICT` | 提示「数据已被他人修改，请刷新后重试」 |
| 列表与设置页数据刷新 | 展示值非最新 | 保存成功后仅刷新表内该行值；列表数据不做乐观更新 | 表内值即时正确 |
| 多 Tab 同时打开本模块 | 状态互相覆盖 | 状态键为会话级 sessionStorage，按标签页隔离 | 各自独立，互不干扰 |

## 6. 接口与前后端契约

> 本节定义产品语义；最终以 OpenAPI 文档同步为准。以下路径为**建议命名**，须与后端确认（O-10）。

### 6.1 接口清单

| 场景 | Method & Path | 鉴权 | 请求关键参数 | 响应关键字段 | 失败语义 |
|---|---|---|---|---|---|
| 返佣汇总列表 | `GET /api/v1/rebate/accounts` | `rebate.view` | `page, pageSize, keyword, sortField, sortDir` | `items[{ id, phone, email, account, totalCommission, frozenCommission, withdrawable, totalWithdrawn, inviteCount, ratio }], total` | `FORBIDDEN`、`INVALID_FILTER` |
| 返佣明细列表 | `GET /api/v1/rebate/details` | `rebate.view` | `page, pageSize, orderNo, orderType, createdFrom, createdTo, invitee, inviter` | `items[{ orderNo, orderType, createdAt, invitee, inviter, pay, ratio, amount, status, rebateAt, inviterWithdrawable }], total` | 同上 |
| 冻结明细列表 | `GET /api/v1/rebate/freezes` | `rebate.view` | 同返佣明细 | `items[{ ..., freezeAmount, freezeStatus, doneAt, unfreezeAt }], total` | 同上 |
| 邀请明细列表 | `GET /api/v1/rebate/invitations` | `rebate.view` | `page, pageSize, inviter, invitee, invitedFrom, invitedTo, inviteStatus` | `items[{ seq, inviter, invitee, invitedAt, status, paidTotal, consumeTotal, ratio, commission }], total` | 同上 |
| 提现明细列表 | `GET /api/v1/rebate/withdrawals` | `rebate.view` | `page, pageSize, phone, email, username, userId, createdFrom, createdTo` | `items[{ userId, phone, email, account, balance, type, amount, createdAt }], total` | 同上 |
| 返佣设置读取 | `GET /api/v1/rebate/settings` | `rebate.view` | — | `{ ratio: [{key,name,value}], withdraw: [{key,name,value}], version }` | `FORBIDDEN` |
| 返佣设置更新 | `PATCH /api/v1/rebate/settings/{key}` | `rebate.setting.update` | `{ value, version, idempotencyKey }` | `{ key, value, version }` | `VALIDATION_ERROR`、`VERSION_CONFLICT`、`FORBIDDEN` |

**契约要点：**
1. 列表接口一律返回 `total` 用于分页；**排序由服务端执行**（前端当前为本地排序，接入后需迁移，见 O-02）。
2. 「明细」下钻不新增接口，复用目标 Tab 的列表接口并携带对应筛选参数。
3. 金额字段一律以**字符串或分为单位的整数**传输，避免浮点误差；展示层负责转 `￥` 格式。
4. 时间字段统一 ISO 8601（含时区）或 `YYYY-MM-DD HH:mm:ss`【待确认】，避免前后端时区歧义。

### 6.2 通用响应与错误约定

```JSON
{
  "requestId": "req_xxx",
  "code": "VALIDATION_ERROR",
  "message": "请求参数不合法",
  "fieldErrors": [{"field": "value", "code": "OUT_OF_RANGE", "message": "返佣比例需在 0 ～ 100 之间"}]
}
```

| 错误码 | 前端处理 | 是否重试 | 用户文案 | 日志级别 |
|---|---|---|---|---|
| `UNAUTHENTICATED` | 刷新令牌 / 跳登录 | 是（一次） | 登录已过期，请重新登录 | warn |
| `FORBIDDEN` | 保持页面并刷新权限态 | 否 | 您没有权限执行此操作 | warn/audit |
| `VALIDATION_ERROR` | 字段级展示接口返回文案 | 否 | 使用接口返回文案 | info |
| `VERSION_CONFLICT` | 拉取最新设置 | 否 | 数据已被他人修改，请刷新后重试 | warn |
| `RATE_LIMITED` | 倒计时禁用 | 是（按 `retryAfter`） | 操作过于频繁，请稍后再试 | warn |
| `INTERNAL_ERROR` | 不丢失输入，允许重试 | 是（幂等写） | 系统异常，请稍后重试 | error |

### 6.3 异步任务约定（如适用）

**不适用。** 本模块无导出/批量处理等异步能力；若后续开放导出（O-05），须按模板补齐 `taskId`、轮询、进度与产物过期规则。

### 8.3 审计与告警

关键写操作审计字段：`operatorId、operatorRole、targetType(=rebate_setting)、targetId(=settingKey)、action(=update)、before、after、requestId、ipHash、createdAt`。

告警阈值建议：【待填】——设置类接口错误率、`FORBIDDEN` 频次异常（越权尝试）、依赖服务超时率。
