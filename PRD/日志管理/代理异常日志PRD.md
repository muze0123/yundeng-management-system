# 代理异常日志 PRD

> 产品：云登后台管理系统
> 模块：日志管理 / 代理异常日志
> 需求类型：新建
> 优先级：P1
> 目标端：Web PC（设计基准 ≥1280px，最低支持 1024px）
> 文档日期：2026-10-10
> 状态：可直接用于 Vibecoding（原型已实现并完成运行时验证）

## 0. 文档依据与执行约束

实现前依次读取本 PRD、`design.md`、`claude.md`、《系统框架PRD.md》与《分页器PRD.md》。

- 一级菜单「日志管理」为本轮新增，二级菜单仅「代理异常日志」一项（`section-log` / `proxy-exception-log`）。
- 原型路由：`index.html?page=proxy-exception-log`；兼容入口 `Prototype/代理异常日志.html`（`location.replace` 透传查询参数）。
- 业务实现：`Prototype/modules/proxy-exception-log.js`，仅构建内容区，不另建系统壳、不使用 iframe。
- 页面为**只读查询**：不提供编辑、删除、重推、导出与批量操作。

## 1. 问题陈述

代理异常是该产品的核心客诉类型之一。用户反馈「代理用不了」时，客服与研发只能依赖用户口头描述与私聊截图，无法回答以下问题：异常发生在哪台机器、哪个客户端版本、哪个代理资产上；是代理侧问题还是本机网络问题；是单用户偶发还是同版本批量出现。

缺少结构化日志视图会导致：定位链路长（用户 → 客服 → 研发 → 代理供应商）、同类问题重复排查、责任边界（平台 / 用户本机网络 / 供应商）无法举证。

## 2. 解决方案

新增一级菜单「日志管理」与二级页面「代理异常日志」。页面按**企业 / 用户 / 代理 / 客户端版本 / 产生时间**检索客户端上报的代理异常记录，并同时呈现终端环境信息（系统、终端识别码、MAC、本机网络），使排查方可在一次查询内区分「代理侧异常」与「终端环境异常」。

页面只做检索与呈现，不做处置动作；处置仍走既有的「更换代理」与工单流程。

## 3. 页面定位与成功指标

代理异常日志是日志管理域下的只读排查页面，承接客服工单、用户反馈与代理质量巡检，输出可定位到具体终端与代理资产的原始记录。

| 指标 | V1 目标 |
|---|---:|
| 常规查询 P95 | ≤3 秒 |
| 首页渲染 P95 | ≤1.5 秒 |
| 客诉首次定位耗时降低 | ≥40% |
| 越权读取其他企业数据 | 0 |
| 敏感字段原值泄露 | 0 |

## 4. 用户故事

1. 作为客服，我想按用户ID检索异常日志，以快速确认用户报障是否属实。
2. 作为客服，我想看到代理IP与所属地区，以判断是否与用户描述一致。
3. 作为代理运营，我想按代理ID聚合排查，以确认某条代理资产是否被集中反馈。
4. 作为研发，我想按客户端版本筛选，以判断异常是否集中在某个版本。
5. 作为研发，我想看到系统名称、系统版本与终端识别码，以判断是否是终端环境问题。
6. 作为研发，我想看到本机网络，以区分本机网络异常与代理侧异常。
7. 作为代理运营，我想按产生时间区间检索，以核对某个窗口内的集中反馈。
8. 作为企业管理员，我想按企业ID检索，以核对本企业名下的异常记录。
9. 作为审计人员，我想确认查询行为被留痕且不返回代理账号密码等凭证。
10. 作为用户，我想在查询失败时保留筛选条件与旧结果，以便重试。

## 5. 信息架构

```text
日志管理（一级，可展开）
└─ 代理异常日志（二级，唯一子项）
   ├─ 筛选区
   │  ├─ 企业ID / 用户ID / 代理ID / 代理名称
   │  ├─ 客户端版本（下拉单选）
   │  └─ 产生时间（日期范围）
   ├─ 数据区
   │  ├─ 标题栏：代理异常日志 + 结果条数
   │  ├─ 数据表格（13 列）
   │  └─ 分页器
   └─ 日期范围浮层（月历）
```

一级菜单「日志管理」使用 `scroll-text` 图标，位于「数据埋点」之后；二级菜单不显示功能图标、不额外缩进（对齐一级菜单文字起点）。

## 6. 筛选与查询规则

筛选控件遵循 `design.md` §5.4：`.filter-flow` 自适应栅格（基准 388px）、`.filter-label` 右对齐并带中文全角冒号、操作组 `.filter-actions`（间距 12px、高 32px、不拆分）跟随最后一项条件。文本框提供清空按钮。

| 字段 | 类型 | 匹配规则 |
|---|---|---|
| 企业ID | 文本 | 包含匹配（子串） |
| 用户ID | 文本 | 包含匹配（子串） |
| 代理ID | 文本 | 包含匹配（子串） |
| 代理名称 | 文本 | 包含匹配，忽略大小写 |
| 客户端版本 | 下拉单选 | 精确匹配；默认「全部」 |
| 产生时间 | 日期范围 | 闭区间，按自然日比较（含首尾日） |

交互口径：

- 条件之间为 AND，各字段内部无多选。
- 输入只更新草稿（draft），点击「查询」才写入已应用条件（applied）并重置到第 1 页。
- 「重置」清空全部 6 项条件（含日期区间与下拉），恢复到第 1 页全量结果。**必须逐控件清空而非依赖 `form.reset()`** —— 日期区间由隐藏域承载，`form.reset()` 不复位隐藏域，会导致重置后日期条件残留。
- 日期浮层：点击日期按钮展开双月历；先选开始、再选结束；选择顺序颠倒时自动交换；「清空」清除区间，「确定」写回；`Escape` 关闭并回焦到触发按钮；点击浮层外部关闭。

## 7. 数据列表

### 7.1 列定义（13 列，严格按此顺序）

| # | 列名 | 展示口径 |
|---:|---|---|
| 1 | 企业ID | 等宽字体，原值 |
| 2 | 用户ID | 等宽字体，原值 |
| 3 | 用户账号 | 手机号或邮箱，位于用户ID右侧；见 §7.3 |
| 4 | 代理ID | 等宽字体，原值 |
| 5 | 代理名称 | 原值 |
| 6 | 代理信息 | 见 §7.2，两行式复合单元格 |
| 7 | 客户端版本 | 等宽字体，如 `4.0.2.4` |
| 8 | 系统名称 | 如 `Windows`、`macOS`、`Ubuntu` |
| 9 | 系统版本 | 等宽字体，如 `10.0.22631` |
| 10 | 终端识别码 | 等宽字体，32 位十六进制终端指纹 |
| 11 | MAC地址 | 等宽字体，大写冒号分隔，如 `8C:85:90:1F:2B:7C` |
| 12 | 本机网络 | 网络类型（灰色小字）+ ` · ` + 内网地址（等宽字体） |
| 13 | 产生时间 | 等宽字体，`YYYY-MM-DD HH:mm:ss` |

- 表格整体左对齐；所有数字、ID、版本、时间、指纹、MAC 使用 `font-mono`（`JetBrains Mono` + `tabular-nums`），保证列内数字对齐。
- 表格最小宽度 2000px，容器横向滚动，不换行折行。
- 默认按产生时间倒序（最新在前），当前版本不提供列排序。
- 标题栏（`代理异常日志` + `共 N 条`）与数据表**直连**，中间无分割线；仅在存在 KPI 指标卡或批量操作工具条时才需要分割线。

### 7.2 「代理信息」单元格口径

复合单元格，两行结构：

```text
204.141.248.68        ← 第一行：代理IP（等宽）+ 悬停/聚焦显示的复制按钮
[平][静] 美国-洛杉矶   ← 第二行：代理标签 + 所属地区（灰色小字）
```

- **代理IP**：等宽字体；行内附复制按钮，默认透明，单元格悬停或按钮聚焦时显现（`#F0F1F3` 底 / `#9DA2AC` 字），点击复制该 IP 并弹出 Toast「代理IP已复制」；复制失败提示「复制失败，请手动选择复制」。
- **代理标签**：18×18px 圆角描边方形徽标，`border:1px solid currentColor`，白底。**「平」与「静」是两个相互独立、可同时出现的维度**（口径 2026-10-10 经用户确认）：
  - `平` = **平台代理**（代理来源），文字与描边色取 `warning` 令牌 `#E7772D`
  - `静` = **静态代理**（网络类型），文字与描边色取 `success` 令牌 `#0FC060`
  - 自有代理（`self`）**不输出任何徽标**（不输出占位、不输出 `undefined`）；动态代理不输出 `静`。
  - 标签必须带 `title` 补充完整语义（「平台代理」/「静态代理」），因单字标签自身不可自解释。
- **所属地区**：`{国家/地区}-{城市}`，灰色 12px。涉及中国港澳台时统一写为「中国-香港」「中国-澳门」「中国-台湾」。

### 7.3 「用户账号」列口径

- 位置固定在**用户ID右侧（第 3 列）**，与用户ID构成「标识 + 账号」的相邻信息组。
- 取值是**单一账号标识**，两种形态互斥：**手机号**（11 位数字）或**邮箱**。同一用户ID在同一时间只对应一个账号，不存在一列同时展示手机号与邮箱。
- 字体策略：纯数字（手机号）使用 `font-mono`；含字母的邮箱使用正文字体。二者共用同一列，列宽按最长取值自适应。
- **不参与筛选**：本轮筛选区保持 6 项不变，用户账号为展示字段。（如需按账号检索，见 O-06。）
- **展示口径（已定稿，2026-10-10）**：**手机号 / 邮箱一律明文原值展示，不脱敏**。`claude.md` §六 已于 2026-10-10 同步修订——移除「账号、邮箱、手机号必须脱敏」的强制要求，改为「手机号、邮箱、账号一律使用明文，仅代理凭证（key / secret / token / 密码）必须脱敏」。故本条与规范文档已无冲突（原争议记录见第 14 章 O-07）。

## 8. 分页

遵循《分页器PRD.md》与 `design.md` §5.5：分页器位于数据卡片内部、表格右下方，不与表格拆成独立卡片。

- 页码导航（首尾页 + 当前页 ±1 + 省略号）、每页条数（10 / 20 / 50，默认 20）、跳页输入框、`共 N 条记录　第 p/pages 页` 统计。
- 跳页输入框默认值恒为 `1`；输入非法页码时提示「请输入 1 至 N 之间的有效页码」并复位为 `1`。
- 筛选条件变更后重置到第 1 页；页码越界时自动收敛到有效范围。

## 9. 状态与边界

| 状态 | 表现 |
|---|---|
| 加载中 | 内容区骨架屏，保留侧栏与筛选区 |
| 有结果 | 标题栏显示结果条数与总数 |
| 空结果 | 表格内单行空态：搜索图标 + 「暂无符合条件的代理异常日志，请调整筛选条件或重置」，`colspan="12"` |
| 查询失败 | 保留筛选条件与上一次结果，Toast 提示可重试 |
| 无权限 | 展示缺失权限，不展示空列表 |

## 10. 权限、安全与审计

- 数据范围按登录账号的授权企业裁剪；服务端必须先完成租户裁剪再返回。
- 列表**不得**返回代理账号、密码、密钥等凭证字段；仅展示代理IP与资产元信息。
- 本机网络与 MAC 属于终端设备信息，按最小必要原则展示，仅授权角色可见。
- 查询行为留痕：操作人、查询条件、时间范围、结果条数、导出（当前版本无导出）。

## 11. 页面状态恢复

- 切换路由前保存筛选控件值、已应用条件、分页游标与每页条数、滚动位置；返回时恢复。
- 模块内状态使用 `sessionStorage`（键 `yundeng-proxy-exception-log-v1`），与框架层的模块状态捕获机制协同；侧栏折叠与菜单展开态由框架层用 `localStorage` 维护。

## 13. 非目标范围

- 不做异常自动归因、聚类与告警推送。
- 不做日志导出、批量选择、批量操作。
- 不做时间趋势图、KPI 指标卡与代理质量评分。
- 不做原始日志全文检索与原始报文查看。
- 不做异常处置动作（更换代理、下架代理、通知用户）。
