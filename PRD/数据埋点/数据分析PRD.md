# 数据分析 PRD

> 所属模块：数据埋点 / 数据分析
> 路由：`/data-tracking/analysis`  
> 优先级：P0  
> 状态：可直接用于 Vibecoding

## 1. 问题陈述

产品和数据人员需要把统一事件字典转化为可重复的事件、漏斗、留存、路径和分群分析。若配置、查询结果和指标口径混在一起，筛选变化会篡改旧结果，异步查询无法恢复，未成熟周期和分母为零会被误读，废弃事件也可能让历史分析失效。

## 2. 解决方案

提供五个分析 Tab：事件分析、漏斗分析、留存分析、路径分析、用户分群。左侧配置、右侧结果；运行时生成不可变 query snapshot 和异步 taskId。结果可保存分析、另存为看板卡片或复制脱敏链接。

## 3. 用户故事

1. 作为分析师，我想查看事件次数、人数和人均次数。
2. 作为产品经理，我想构建 2–10 步漏斗并设置最大间隔。
3. 作为产品经理，我想按个人/企业认证拆分实名漏斗。
4. 作为分析师，我想计算日/周/月留存并识别未成熟周期。
5. 作为分析师，我想从起点或终点探索用户路径。
6. 作为分析师，我想用属性和行为条件建立动态分群。
7. 作为用户，我想保存分析配置并复用。
8. 作为用户，我想把结果保存为看板卡片。
9. 作为用户，我想在查询中离开页面后恢复任务。
10. 作为用户，我想在修改配置后明确知道旧结果已失效。

## 4. 页面结构

```text
FilterSection：全局日期 / 团队 / 客户端 / 版本
DataSection
├─ Tab：事件 / 漏斗 / 留存 / 路径 / 分群
├─ AnalysisBuilder（左 360px）
└─ ResultPanel（右侧自适应）
   ├─ QueryStatus
   ├─ Chart / Table
   └─ 保存分析 / 保存到看板 / 导出聚合
```

1024–1279px 配置区改为顶部折叠面板；结果区保持至少 640px。配置区和结果区各自滚动，但页面仍只有主内容为纵向主滚动容器。

## 5. 公共分析规则

| 项目 | 规则 |
|---|---|
| 事件选择 | 只显示 online/deprecated；deprecated 可查历史并带标识 |
| 属性 | 只显示事件 Schema 中允许分析的非 forbidden 属性 |
| 条件 | 同组 AND，组间可选 AND/OR；最多 20 条 |
| 时间 | 最大 730 天；>90 天默认周，>730 不允许 |
| 分群 | 最多 3 个 groupBy；预计序列 >10 时预警 |
| 运行 | 生成 query snapshot，不随编辑区变化 |
| 结果 | 必须展示时间、时区、去重、窗口、更新时间 |
| 分享 | 只分享分析 definitionId，不在 URL 放入用户标识或原始条件值 |

配置变化后 result.staleByConfig=true，结果顶部显示“配置已变更，重新运行后更新结果”；旧结果仍可读但不可直接覆盖保存。

## 6. 事件分析

选择 1–5 个事件；指标为事件次数、用户数、环境数、人均次数、转化率；支持时间粒度、分组属性、过滤和周期对比。多事件指标定义不同则禁止叠加到同一轴。点击图例隐藏序列；表格与图表共用结果。

## 7. 漏斗分析

步骤 2–10，每步选择事件和步骤过滤；默认用户级去重，可切换事件级。最大间隔：30 分钟、24 小时、7 天、30 天、自定义。转化按有序发生计算；同一用户多次完成默认取首次，可切换全部完成次数。

内置模板：新用户激活、代理首购、购后价值、环境编辑、团队协作、自动化采用。实名模板必须提供 auth_type=personal/enterprise 分群。拖拽或键盘排序步骤后旧结果失效。分母为 0 显示“—”。

## 8. 留存分析

配置起始事件、回访事件、日/周/月单位、1–24 个周期和分群。cohort 按首次满足起始事件的周期归组；同一用户不重复进入同一分析的多个 cohort，除非选择“滚动 cohort”。未成熟周期使用斜线并显示“数据未完整”，不参与平均。

## 9. 路径分析

选择起点或终点事件，最大步数 3–10，会话超时默认 30 分钟。Sankey 显示 Top 8 节点，其余合并“其他”；连续重复事件合并并显示次数。点击节点可设为新起点/终点；循环路径不无限展开。提供路径数据表作为无障碍替代。

## 10. 用户分群

属性条件 + 行为条件，最多 20 条，支持 AND/OR。预估人数采用异步任务；结果只显示聚合人数、占比和趋势，不显示用户身份。分群类型：dynamic 每日更新，snapshot 固定生成时结果。保存前展示自然语言摘要，属性删除/废弃时标记条件失效并阻止更新。

## 11. 状态管理与异步数据流

1. Builder 维护 draftDefinition；点击运行深拷贝为 querySnapshot；
2. 创建任务返回 taskId 和 queued；前台 2 秒轮询，30 秒后退避为 5 秒；
3. 离开页面停止轮询但任务继续；返回后按 taskId 恢复；
4. 取消只允许 queued/processing，成功后状态 cancelled；
5. 成功结果写入 resultCache[queryHash]，缓存 10 分钟；
6. 保存分析使用 snapshot，不保存未运行 draft；
7. 保存到看板打开 Modal，选择看板、卡片名、尺寸；成功不跳离当前页；
8. 新请求生成后旧任务完成不得覆盖当前结果。

## 12. 加载中、空状态、错误 与边界

| 状态 | 表现 |
|---|---|
| 初始 | 提示“配置分析条件后运行” |
| queued/processing | 真实 progress、阶段文案、可取消条件 |
| Empty | “当前条件下暂无可分析数据”，保留配置 |
| partial_fail | 显示可用结果和失败分组清单 |
| failed | 显示原因、重试；不清空配置 |
| expired | “结果已过期，请重新运行” |
| Event deprecated | 可查废弃前历史，日期越界时警告 |
| 序列过多 | 预估 >50 阻止运行；11–50 提示 Top 合并 |
| 超时 | 提示缩小日期/减少条件并允许复制配置 |

## 13. 权限与安全

`analysis.read/create/update/delete/export`、`cohort.manage`。运营只读授权分析。禁止结果展示直接身份；低于隐私阈值的分群显示“<10”而非精确人数；所有分享和导出写审计。

## 14. 接口契约

| 场景 | 接口 |
|---|---|
| 事件/属性选择器 | `GET /api/v1/tracking/analysis/context` |
| 创建任务 | `POST /api/v1/tracking/analysis-tasks` |
| 任务状态 | `GET /api/v1/tracking/analysis-tasks/{taskId}` |
| 取消任务 | `POST /api/v1/tracking/analysis-tasks/{taskId}/cancel` |
| 保存分析 | `POST /api/v1/tracking/analyses` |
| 保存分群 | `POST /api/v1/tracking/cohorts` |

错误：QUERY_TOO_LARGE、QUERY_TIMEOUT、INVALID_EVENT_WINDOW、PROPERTY_DEPRECATED、PRIVACY_THRESHOLD、TASK_EXPIRED。

## 15. 模拟数据与门户标注

至少 12 个事件、20 个属性、6 个漏斗模板、8 个 cohort 周期、15 条路径边、6 个分群示例；覆盖成功、空、部分失败、超时、取消、过期和隐私阈值。

标注覆盖五个 Tab、事件选择、条件构建、分群、步骤排序、最大间隔、运行、取消、结果口径、图表/表格、保存分析和保存到看板。

## 16. 测试决策

使用 `analysisDraft → querySnapshot → asyncTask → result` 作为测试接缝。验收：

1. draft 变化不篡改已完成结果；
2. 旧任务不覆盖新查询；
3. 五类分析规则和空/失败状态正确；
4. 实名 personal/enterprise 可分群；
5. 未成熟留存不计入平均；
6. 分母 0 显示“—”；
7. 任务可恢复、取消和过期；
8. 保存看板使用已运行 snapshot；
9. 隐私阈值和权限生效。

## 17. 非目标范围

自助 SQL、用户明细、机器学习预测、多触点归因、实时秒级分析和自动生成产品结论。

## 18. 页面布局详细规格与业务模板（V1.1 补充）

```text
Main（高度 = viewport - TopBar）
├─ AnalysisTypeBar（48px）：事件 / 漏斗 / 留存 / 路径 / 分群
└─ Workspace（最小高 720px）
   ├─ BuilderPanel（360px，左侧独立滚动）
   │  ├─ 模板选择 / 事件或步骤配置
   │  ├─ 属性筛选与分群 / 窗口与去重
   │  └─ 运行分析
   └─ ResultPanel（剩余宽度）
      ├─ ResultHeader：保存 / 创建洞察
      ├─ QueryStatusBar
      ├─ Visualization（图表/数据表）
      ├─ BreakdownTable
      └─ DefinitionPanel（口径与限制）
```

BuilderPanel 在 ≥1280px 固定左侧；1024–1279px 改为顶部可折叠配置区。事件、漏斗、留存、路径、分群的主可视化最小高度分别为 360、440、420、480、360px，全部提供同数据源表格替代。

新增预置模板：新用户激活；订阅转化；代理购买与实际使用；个人/企业实名与原任务恢复；核心场景与入口效率；版本发布效果；激活/留存驱动。模板仅预填配置，运行时仍引用已发布事件与指标版本；驱动分析只报告相关关系，不自动宣称因果。

布局验收：五类分析配置互不污染；异步任务所有状态保持结构；模板结果可追溯模板/事件/指标版本；“创建洞察”冻结分析快照与限制；1024px 下配置可折叠且无双重滚动；漏斗 20 步、路径 100 节点和未成熟留存周期布局稳定。
