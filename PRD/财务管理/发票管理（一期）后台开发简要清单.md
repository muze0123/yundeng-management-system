# 发票管理（一期）· 后台开发简要清单

> **用途**：告知项目组一期做什么、不做什么、有哪些硬约束。
> **必读**：研发 / 测试 / 设计 请同时阅读 `PRD/财务管理/发票管理（一期）PRD.md`（一期唯一开发基线）。
> **母文档**：`PRD/财务管理/发票管理PRD.md`（V2.2，含二期完整规则）。
> **版本**：v1.0 / 2026-09-18

---

## 一、一句话结论

一期只做「**申请管理 + 票据管理**」两个 Tab，把「用户申请开票 → 财务审核 → 第三方开具蓝票 → 交付用户」这条链路跑通并稳定。**红冲任务、开票配置两块不做**，二期再做。

---

## 二、一期做什么

### 2.1 页面与功能

| # | 页面 / 能力 | 内容 |
|---|---|---|
| 1 | 财务管理菜单 + 发票管理路由 | 新增「财务管理 > 发票管理」菜单；入口 `index.html?page=billing-invoice&invoiceTab=applications` |
| 2 | **申请管理 Tab** | 列表（18 列 / 16 条 Mock）、筛选（10 项）、分页、详情抽屉、导出 |
| 3 | 申请审核 | 待审核申请直接「审核通过 / 驳回」，无领取锁；驳回含结构化原因 |
| 4 | 管理员代客申请 | 「新增开票申请」三步弹窗（选择客户订单 → 填写信息 → 核对提交） |
| 5 | 团队限额提醒 | 团队累计 ≥ ¥2,000.00 时提醒「请核实合同」，**仅提醒不阻断** |
| 6 | **票据管理 Tab** | 列表（14 列 / 11 条 Mock）、筛选（4 项）、详情抽屉 |
| 7 | 票据文件能力 | 预览（已归档 PDF）、下载（PDF/OFD/XML）、文件补拉、（可选）异步打包 ZIP |
| 8 | 票据交付 | 站内 + 邮件双渠道交付单元、交付失败重发 |
| 9 | 开具异常处置 | `UNKNOWN` 只查询；`FAILED` 重试或「关闭旧任务并要求补正」；队列恢复 |
| 10 | 第三方对接 | Provider Adapter、回调 Inbox（验签/去重/乱序）、主动查询退避、日终对账 |
| 11 | 权限与审计 | 4 类角色、开票主体数据范围、关键操作审计、异步导出 |

### 2.2 页面字段基线（以原型实测为准，勿再改动）

**申请管理筛选（10 项，顺序固定）**
申请单号(input) → 发票类型(select) → 发票抬头(input) → 发票号码(input) → 开票订单(input) → 申请状态(select) → 开具状态(select) → 票据状态(select) → 交付状态(select) → 申请时间(日期范围)

**申请管理列表（18 列，顺序固定）**
申请单号 / 发票类型 / 发票抬头 / 发票号码 / 开票金额 / 发票内容 / 税率 / 团队ID / 申请人 / 申请时间 / 开票订单 / 联系邮箱 / 申请状态 `?` / 审批人 / 开具状态 `?` / 票据状态 `?` / 交付状态 `?` / 操作

**票据管理筛选（4 项）**：关键词 → 票据状态 → 交付状态 → 开具时间

**票据管理列表（14 列）**
票据ID / 发票类型 / 发票抬头 / 发票号码 / 开票金额 / 团队ID / 申请人 / 交付渠道 / 联系邮箱 / 开具时间 / 申请单号 / 票据状态 `?` / 交付状态 `?` / 操作

**工具栏**：申请管理 = 刷新 / 导出 / 新增开票申请（主按钮）；票据管理 = 刷新 / 导出。一期**无**批量选择、**无**指标卡、**无**状态快捷 Tab。

| N6 | 组合支付按法币分摊开票 | 整体不支持 |
| N7 | 自动免审、双人复核、复杂金额风控 | 不做 |

| N9 | 申请列表批量选择与批量审批 | 不做 |

## 四、状态口径速查（一期）

### 4.1 四维状态（正交，不可合并）

| 维度 | 一期可用值 |
|---|---|
| 申请 `application_status` | 待审核 `PENDING_REVIEW`、审核通过 `APPROVED`、已驳回 `REJECTED`、已撤回 `WITHDRAWN`、已取消 `CANCELLED` |
| 开具 `issuance_status` | 未提交 `NOT_SUBMITTED`、提交中 `SUBMITTING`、开具中 `ISSUING`、开具成功 `SUCCEEDED`、开具失败 `FAILED`、结果未知 `UNKNOWN` |
| 票据 `document_status` | **仅 未生成 `NONE`、有效 `ACTIVE`**（其余 4 值二期启用） |
| 交付 `delivery_status` | 未发送 `NOT_SENT`、发送中 `SENDING`、部分送达 `PARTIALLY_DELIVERED`、已送达 `DELIVERED`、交付失败 `FAILED` |

### 4.2 下拉筛选枚举（按原型，勿改）

- **申请状态**：全部 / 待审核 / 审核通过 / 已驳回 / 已撤回 / 已取消
- **开具状态**：全部 / 未提交 / 提交中 / 开具中 / 开具成功 / 开具失败 / 结果未知
- **票据状态**：全部 / 有效 / 红冲中 / 部分红冲 / 已红冲 / 红冲失败 / 未生成 ← 一期只可能命中「有效」「未生成」
- **交付状态**：全部 / 未发送 / 发送中 / 已送达 / 交付失败

> 命名口径统一为「**开具中**」（不用「开票中」）、「**审核通过**」（不用「已通过」）。红冲类词（红冲处理中 / 已全额红冲 / 已部分红冲 / 部分红冲成功）全部停用。

### 4.3 单据派生状态优先级（一期）

开票失败/结果未知 > 已开票 > 开具中 > 已驳回 > 待审核 > 已撤回/已取消

## 五、硬约束与前置依赖（有阻塞项，务必先确认）

| # | 约束 | 说明 | 责任方 |
|---|---|---|---|
| **K1** | **一期无开票配置页面，配置数据靠初始化脚本** | 开票主体、发票内容、税收分类编码、税率、SKU 映射、第三方账号与密钥，需财务线下书面确认后由研发以脚本写入；变更走工单 + 研发执行 + 变更后回归。**无配置数据则无法审核通过、无法开票，直接阻断上线** | 财务 + 技术 |
| **K2** | **一期无红冲能力，已开票后退款无法红冲** | 票面金额与退款后应有金额会出现长期差异。一期口径：**不创建红冲任务**，登记人工待办 + 立即告警，账本以 `refund_cents` 单独留痕，**不静默改写** `effective_blue_amount`。上线前必须完成人工处置 SOP | 产品 + 财务 |
| K3 | 第三方平台能力 | 需支持蓝票开具、状态查询、回调、文件获取与沙箱验证 | 技术/采购/财务 |
| K4 | 订单事实稳定 | 订单/支付/履约/退款服务提供稳定 ID、金额单位「分」、版本与幂等事件 | 订单/支付技术 |
| K5 | 权限中心 | 支持一期功能权限点 + 开票主体 + 团队/业务数据范围 | 权限平台 |
| K6 | 账本核心不变量 | 任一订单：`有效申请占用 + 有效蓝票金额 ≤ 已确认法币实付 − 已确认法币退款` | 技术 + 财务 |
| K7 | 写操作一致性 | 全部写接口：`request_id` 幂等 + 对象 `version` 条件更新 + 事务 Outbox；`UNKNOWN` 只能查询，禁止盲重试 | 技术 |
| K8 | 敏感字段 | 税号/联系邮箱在授权页面完整展示；银行账号/电话默认脱敏；均不进入 URL、sessionStorage、普通日志、埋点 | 前后端 + 安全 |
| K9 | 金额与时区 | 金额以「分」整数计算、页面两位小数；时区 `Asia/Shanghai` | 前后端 + 数据 |
