# 用户提现 PRD

更新日期：2026-09-16

## 1. 范围与入口

订单管理 → 用户提现，统一入口 `index.html?page=user-withdrawal`，实现文件 `Prototype/modules/user-withdrawal.js`。旧 `Prototype/用户提现.html` 保留兼容跳转。复用公共系统框架，不新增菜单或独立页面壳层。

页面用于查看用户周期内的提现汇总、逐笔申请明细及发起审批。以参考图的列表字段、明细表格和操作入口为依据；视觉执行 `design.md`。本次为 Mock 原型，不触发真实审批或资金支付。

## 2. 数据口径

- 一行代表一个用户在一个申请周期、同一提现方式和收款账号下的申请汇总。此聚合键为本次推断补全，接入真实接口时需业务确认。
- 申请笔数 = 该汇总下明细条数；提现总额 = 明细金额之和。内部使用整数分计算，显示为人民币元、两位小数。
- 账户余额为独立账户数据，不等于提现总额；发起审批不变更余额。
- 手机号、邮箱、代理商子账号完整显示，不做脱敏，适用于主列表、申请明细及审批确认；提现账号继续使用脱敏数据；无代理商子账号、审核备注或完成时间时显示“—”。
- 默认提供 12 条汇总，覆盖待审核、审核中、审核成功、审核驳回。第一条含 12 笔明细，可切换 10 条/页验证明细分页。其余每条包含 3–6 笔。
- 待审核、审核中无完成时间；审核成功和审核驳回展示审核流程结束时间，不代表实际打款时间。示例申请时间均位于对应周期内，完成时间晚于周期内申请。

## 3. 筛选区

| 字段 | 控件与规则 |
| --- | --- |
| 手机号 | 文本框，匹配完整手机号，支持完整号码或部分号段查询；支持清空 |
| 邮箱 | 文本框，不区分大小写匹配完整邮箱；支持清空 |
| 代理商子账号 | 文本框，不区分大小写匹配完整子账号；支持清空 |
| 提现方式 | 全部、支付宝、微信 |
| 审核状态 | 全部、待审核、审核中、审核成功、审核驳回 |
| 申请周期 | 双月日期范围选择器，所选范围与记录申请周期有交集即匹配，包含边界 |
| 完成时间 | 双月日期范围选择器，按完成日期匹配，包含边界；选择后排除未完成记录 |

筛选条件以“且”组合。查询提交当前条件并回到第 1 页；输入、选日期、清空单个字段不立即查询。重置清空全部条件并恢复全部结果、第 1 页，保留每页条数。Enter 可提交文本筛选。

日期组件第一次选择开始、第二次选择结束，反向选择自动交换，支持同日；完整选择后可确定，清空后确定移除范围。点击外部或 Escape 关闭且不提交未确认选择；日期浮层支持视口边缘定位，窄屏双月纵排。

## 4. 汇总列表

保留以下独立字段：用户ID、手机号/邮箱/代理商子账号、账户余额（元）、申请笔数、申请周期、提现方式、提现总额（元）、提现账号、账号姓名、审核状态、审核备注、完成时间、操作。

- 联系方式在单元格分行展示，空值显示“—”；申请周期分两行，金额统一两位小数。
- 待审核使用警告色，审核中使用信息色，审核成功使用成功色，审核驳回使用错误色；使用同一套 Badge 样式。
- 仅待审核显示“发起审批”；所有状态均可查看“申请明细”。操作以记录 ID 绑定，筛选/分页后不会错位。
- 标题“提现申请列表”后紧邻真实查询总数，标题栏下方不显示分割线；无独立页面标题或装饰指标卡。
- 表格使用 `.data-table`，全部列左对齐，数字、金额、编号、账号及时间使用等宽字体。字段较多时在表格容器内横向滚动。
- 空结果在表格内展示空状态及调整筛选提示，总数显示 0。

## 5. 申请明细弹窗

点击当前行“申请明细”，打开居中 Modal，不使用详情抽屉。标题“申请明细”，右上角关闭；采用设计规范 760px 宽、最大 92vw、最大 90vh，明细表格横向滚动，内容过高时内部纵向滚动。

- 默认范围仅为当前汇总记录，不混入同一用户其他周期或其他收款账号的申请。
- 顶部为申请时间范围、查询、重置，右侧为“提现 N 笔，共 ¥X.XX”。空间不足时自然换行。
- 筛选申请时间按日期含首尾边界匹配；查询回第 1 页，重置恢复当前汇总全部明细。
- 汇总数字统计弹窗当前筛选结果的全部记录，不仅统计当前页；未筛选时与主列表申请笔数、提现总额一致。
- 表格字段：用户ID、手机号/邮箱/代理商子账号、提现金额（元）、提现方式、申请时间、提现账号、账号姓名。
- 弹窗拥有独立分页，关闭后不更改主列表筛选和页码；重新打开从未筛选、第 1 页、20 条/页开始。
- 支持关闭按钮、底部关闭、遮罩和 Escape；日期浮层打开时 Escape 优先关闭日期浮层。锁定背景滚动、约束键盘焦点，关闭后焦点返回触发按钮。

## 6. 发起审批

使用 `design.md` 的 confirm Dialog：600×250px，问号图标、标题“提现审批”。提示“确定发起用户 {完整手机号} 的提现审批？”，同时显示该记录申请笔数和提现总额。

- 取消、右上角关闭、遮罩或 Escape：无状态变更。
- 确定：仅允许待审核记录进入审核中，显示已发起审批反馈，隐藏该行发起审批入口，防止重复发起；当前筛选随状态变化重新计算。
- 不直接变成审核成功，不写入完成时间，不扣减余额，不模拟真实资金流转。
- “审核中”和“审核驳回”为补全审批生命周期的原型状态；本页不提供审核通过、驳回或打款操作。

## 7. 分页与状态恢复

主列表及明细各自使用设计系统完整三区分页器：页码导航、10/20/50 条每页、跳页输入和真实统计，默认 20 条/页。禁止固定或虚构总条数/总页数。

切换页容量回第 1 页；首尾按钮按边界禁用。≤7 页全展示，更多页使用首页/末页/当前页相邻页与省略号。跳页按 Enter 生效，只允许 1 至总页数的整数，无效值展示错误；输入始终恢复为 1。零结果使用第 1/1 页。

主列表草稿条件、已查询条件、页码、页容量以及 Mock 审核中状态在同一浏览器会话保存，刷新及路由返回可恢复。弹窗不持久化。

## 8. 验收清单

1. 首次进入显示 12 条汇总，筛选与重置影响真实数据，总数和分页一致。
2. 切换 10 条/页后主列表第二页显示剩余 2 条；错误跳页、空结果不产生越界。
3. 不同行打开不同明细；默认笔数和金额与主表完全一致。
4. 第一条明细切换 10 条/页可翻页，申请时间筛选同步更新金额、笔数、总页数；无匹配时汇总为 0。
5. 审批取消不变更；确定后仅对应记录成为审核中，操作消失，完成时间仍为空，刷新后保留。
6. 日期反选、同日、清空、外部关闭和 Escape 正常；打开浮层不会触发查询或被容器裁切。
7. 768px 及桌面视口无页面级横向溢出；两张表均可内部横向滚动。
8. 弹窗支持键盘焦点约束及返回、关闭方式完整；控制台无运行时异常，路由切换清理局部监听器。
