## 1. 需求概述

### 1.0.1 页面定位

成员列表是“用户管理”下的平台级成员关系查询与维护页。平台管理员在其授权数据范围内，以成员与团队 / 企业之间的关系记录为列表粒度，完成查找成员、核对主体归属、查看角色权限和关系状态，以及维护角色、启停或解除成员关系。

本页的核心对象不是企业内部的部门节点，也不是平台用户主档。一个平台用户加入多个团队或企业时，可对应多条成员关系记录；相同成员在不同主体下的角色、状态和加入时间可不同。详情、状态变更和移除均必须指向明确的成员关系记录。

本页不负责新增平台用户、创建团队 / 企业、维护部门层级或配置角色权限内容。移除成员仅解除目标成员与目标主体的关系，不应被实现为删除或注销平台用户；对其它主体关系的影响必须为零。

### 1.0.2 用户场景

| 场景 | 前置条件 | 触发与路径 | 成功结果 | 中断 / 恢复 |
|---|---|---|---|---|

### 1.1 背景与问题

已核实的产品边界是：云登后台需要从平台视角查看团队和企业成员，而旧《成员管理PRD》面向单一企业内部，核心结构是组织树、部门管理和添加成员。直接继承旧结构会混淆“平台成员关系查询”与“企业组织设置”两类职责。

字段分组参考原型证明了一种适合高信息密度列表的组织方式：相同数据集按业务目的切换字段视图，筛选条件保持一致，摘要与导出跟随当前视图。成员列表采用该模式，但不继承来源、付费、套餐、生命周期等用户运营字段。

本需求通过五类字段 Tab、统一筛选与摘要、关系级写操作和主账号保护，让管理员先准确定位成员关系，再判断归属、角色与状态，最后执行受控维护。

### 1.2 一句话目标与成功指标

**一句话目标：**让平台管理员在授权范围内，通过同一筛选结果集的五类字段视图，准确定位并安全维护团队 / 企业成员关系。

本期不虚构既有基线或承诺数值。以下只定义可度量口径，基线、目标、数据源和负责人统一在 O-02 关闭后写入：

| 指标 | 定义 | 当前结论 |
|---|---|---|
| 查询成功率 | 成功返回列表与摘要的查询次数 / 有效查询次数 | 口径候选，目标待确认 |
| 关系写操作成功率 | 角色、状态、移除中服务端确认成功的关系条数 / 提交关系条数 | 口径候选，目标待确认 |
| 主账号保护有效率 | 被前端或服务端阻止的主账号禁用 / 移除尝试 / 全部此类尝试 | 必须为 100%，数据源待确认 |
| 导出范围一致率 | 导出记录集与同筛选条件列表记录集一致的验收次数 / 抽检次数 | 必须无错配，自动化方案待确认 |

**数据边界：**点击按钮、出现 Toast 或创建导出请求，不等同于成员关系已更新或导出文件已生成；仅服务端终态可作为成功。

### 1.3 用户、角色与任务

| 用户类型 | 准入条件 | 任务 | 前端表现 |

### 1.5 前置约束与假设

| 类型 | 当前产品约束 | 若底层不成立 | 关联风险 |
|---|---|---|---|
| 数据粒度 | 列表按成员关系记录展示，写操作必须携带 `membership_id` | 无法保证跨主体操作隔离，需先改数据模型 | O-04 |
| 主体范围 | 主体类型至少区分团队与企业；用户只能查看被授权主体 | 不能实现页面定位和对象级鉴权 | O-03、O-15 |
| 状态影响 | 本期要求启停只影响目标主体关系 | 若现有状态是平台账号全局状态，必须暂停启停能力并重新评审 | O-05 |
| 手机号 | 所有界面默认只消费或渲染脱敏值 | 若接口只返回明文，前端仍须即时脱敏且不得持久化 | O-10 |
| 原型边界 | HTML 使用内联 mock 数据演示，不代表已有生产接口、权限码或指标 | 开发不得从原型字符串反推服务端契约 | 第 6、12 章 |

## 2. 信息架构、入口与用户流程

### 2.1 入口与路由

| 入口 | 前置条件 | 页面 / 文件 | 初始状态 | 返回 / 关闭 |
|---|---|---|---|---|
| 侧边栏“用户管理 / 成员列表” | 具备页面查看权限 | 页面标识 `member-list`；原型 `Prototype/成员列表.html` | 默认 Tab“成员识别”；筛选为全部主体、全部状态；高级筛选收起；第 1 页；无勾选 | 离开页面后不保留选择；筛选是否写入 URL 见 O-07 |
| 页面内成员名称 / 详情操作 | 目标关系仍存在且可见 | 当前页右侧详情抽屉 | 加载该 `membership_id` 最新详情 | 关闭后保留 Tab、筛选和页码 |

支持从团队列表以 `成员列表.html?teamId={team_id}` 进入：当 `teamId` 可识别且当前用户有权查看时，自动应用“主体类型=团队、所属主体=该团队”的筛选；参数无效或无权查看时回退全部主体并提示，不暴露主体是否存在。其他通知、任务或成员级深链不在本期范围，统一在 O-15 评审。

### 2.2 主流程

```text
进入成员列表
 -> 校验页面权限并加载筛选枚举

### 3.2 字段 Tab 与摘要

五个 Tab 使用同一筛选结果集与分页数据，只改变摘要和表格列。默认选中“成员识别”；“全部字段”用于综合核对，不作为默认工作视图。

| Tab | 业务问题 | 摘要指标，均按当前筛选全量计算 | 主要展示字段 |
|---|---|---|---|
| 成员识别 | 这是谁，是否为同一成员 | 关系记录数、去重成员数、主账号数、有手机号记录数 | 成员标识、成员名称、脱敏手机号、成员类型、加入时间、最近活跃时间 |
| 主体关系 | 成员属于哪个团队或企业 | 关系记录数、团队数、企业数、跨主体成员数 | 关系标识、主体类型、主体名称、主体标识、关系状态、组织路径、加入时间、最近更新时间 |
| 角色权限 | 成员在当前主体拥有什么角色与权限范围 | 已配置角色关系数、未配置角色关系数、多角色关系数、角色种类数 | 角色名称、角色数量、权限范围摘要、角色更新时间、更新人 |
| 账号状态 | 成员关系当前是否可用 | 已启用数、已禁用数、从未登录数、主账号数 | 关系状态、最近登录时间、最近活跃时间、禁用时间、禁用原因、操作人 |
| 全部字段 | 综合核对一条成员关系 | 关系记录数、去重成员数、团队数、企业数 | 上述可用字段的并集；手机号仍脱敏；不含内部敏感字段和操作日志原文 |

摘要规则：

1. “关系记录数”是命中筛选条件的 `membership_id` 数，不按用户去重。
2. “去重成员数”按 `member_id` 去重。
3. “跨主体成员数”是当前筛选集中拥有两个及以上不同 `subject_id` 的去重成员数。
4. “有手机号记录数”只判断是否存在手机号，不统计或暴露手机号值。
5. “未配置角色关系数”按角色集合为空的关系记录计数；是否允许保存空角色见 O-06。
6. 摘要必须由服务端全量统计或等价的完整数据源计算，不得从当前页前端行数据推算。
7. 切换 Tab 后保留筛选和当前合法页码，清空选择；摘要、列标题和导出字段同步变化。

### 3.4 分页

分页器位于数据卡片内部、表格右下方，结构和视觉严格复用 `design.md` 5.5：页码导航、每页条数、跳页、总记录数与当前页。页码超过 7 页时使用省略号折叠。

1. 首次进入和执行查询 / 重置后为第 1 页。
2. 翻页、跳页或修改每页条数后清空选择，保留 Tab 与筛选。
3. 跳页输入必须是有效正整数；越界时定位至最近有效页，并将输入框恢复为 `1`。
4. 写操作刷新后若当前页无数据，自动回退最近有效页。
5. 默认每页条数、可选条数和默认排序尚未核实，见 O-07；原型 mock 值不得视为生产约定。

### 3.6 角色编辑 Modal

**呈现形态：**760px Modal；标题 `编辑角色`；正文显示成员与主体只读摘要、角色选择器和权限范围只读预览；底部按钮为 `取消`、`保存`。

角色选项必须来自当前主体可用角色集合，不得在前端硬编码为生产数据。选择角色后同步展示服务端提供的权限范围摘要；前端不得自行合并或推断权限。角色是覆盖保存、增量添加还是支持空集合仍待 O-06 确认，在该事项关闭前不得固化生产提交规则。

关闭未保存的角色修改时弹出确认：标题 `确认放弃修改？`，说明 `当前角色选择尚未保存，关闭后将丢失。`，按钮 `继续编辑`、`放弃修改`。

### 3.7 状态与移除 Dialog

确认 Dialog 使用 `design.md` 5.8 的 confirm 类型，移除确认按钮使用 danger 色。Dialog 必须展示具体成员或数量、涉及主体数、影响边界，并明确“不会删除平台账号”。遮罩点击和 ESC 等价于取消，不提交请求。

批量执行仅作用于当前页已选 `membership_id`。请求期间关闭入口禁用；结果按关系逐项返回，部分成功按 B-11 处理。是否支持批量上限、失败明细下载或重试失败项见 O-09，不在原型中伪造。

## 5. 数据模型、业务规则与状态机

### 5.1 领域对象与关系

|---|---|---|---|
| Member | `member_id` | 名称、脱敏手机号、最近登录 / 活跃 | 平台用户在本页的只读识别信息；不在本页新增或删除 |

```

### 5.3 业务规则清单

| 编号 | 规则 | 优先级 / 冲突 | 实现责任 | 验证 |
|---|---|---|---|---|
| R-01 | 一行等于一条成员关系；所有写操作以 `membership_id` 为目标 | 高于姓名、手机号等展示字段 | 前后端 | 同用户跨主体用例 |
| R-02 | 默认条件之间按 AND 组合；Tab 不参与筛选 | Tab 仅控制字段和摘要 | 前后端 | 组合筛选 E2E |
| R-03 | Tab、分页、主体变化和重新查询均清空选择；其它查询条件按 1.0.3 保留 | 主账号从不进入选择集合 | 前端 | 状态切换 E2E |
| R-04 | 摘要、列表和导出必须使用同一筛选语义 | 服务端全量口径优先于当前页推算 | 前后端 / 数据 | 快照一致性测试 |
| R-05 | 当前页全选只选普通成员关系，不跨页 | 主账号保护优先 | 前端 | 混合主账号页测试 |
| R-06 | 主账号不可禁用或移除 | 高于任何角色和批量动作 | 前后端 | 直调接口与 UI 测试 |
| R-07 | 移除只解除指定成员关系，不删除 Member，不改变其它 Membership | 高于旧文档中的“删除成员”语义 | 后端 | 跨主体回归 |
| R-08 | 启停只改变指定成员关系状态 | 若底层为全局状态，按 O-05 阻断上线 | 后端 | 跨主体回归 |
| R-09 | 手机号默认脱敏；缺失显示 `--` | 隐私规则高于导出便利性 | 前后端 | 日志、埋点、导出抽检 |
| R-10 | 写操作以服务端成功为准，前端不提前显示终态 | 失败时保留原状态 | 前端 | 断网 / 失败测试 |
| R-11 | 部分成功必须逐项返回结果，不得整批显示成功 | 成功项刷新，失败项可重试 | 前后端 | 混合结果测试 |
| R-12 | 全部字段是字段并集，不包含明文敏感值、内部权限明细或日志原文 | 数据最小化优先 | 前后端 | 字段白名单测试 |

### 5.4 并发、幂等与一致性

| 场景 | 产品约束 | 用户可见结果 |
|---|---|---|
| 连续点击写操作 | 前端按钮 loading；服务端需提供防重复机制，具体方案见 O-08 | 同一目标只产生一次有效变更 |
| 记录被他人修改 | 请求需携带可校验的版本信息或等价机制，具体见 O-08 | 提示 T-10；刷新最新记录，不静默覆盖 |
| 批量部分成功 | 服务端按 `membership_id` 返回逐项结果 | 成功项刷新，失败项保留并展示原因 |
| 操作后摘要刷新 | 列表、摘要和打开中的详情必须基于同一最新结果 | 不出现列表已禁用而摘要未更新的长期不一致 |
| 导出与列表并发变化 | 导出必须绑定筛选快照或明确的数据时间点 | 文件范围可追溯；实现方式见 O-09 |

### 6.2 通用错误处理

| 失败类别 | 前端处理 | 是否自动重试 | 正式文案 / 状态 |
|---|---|---|---|
| 未登录 | 清除敏感页面数据，进入平台统一登录流程并保留允许的回跳信息 | 仅平台鉴权机制允许时重试一次 | `登录已失效，请重新登录` |
| 无页面或对象权限 | 隐藏无权操作；直达显示无权限态；刷新权限 | 否 | T-09 |
| 筛选或表单校验失败 | 字段级展示，不发起或不重复发起写操作 | 否 | 使用本 PRD 正式文案或服务端可展示业务文案 |
| 主账号保护 | 恢复原状态，清空非法选择，刷新记录 | 否 | `主账号不可执行此操作` |
| 记录不存在 / 已移除 | 关闭失效详情或弹窗并刷新列表 | 否 | `该成员关系已不存在` |
| 并发冲突 | 保留角色编辑选择；刷新关系快照 | 否 | T-10 |
| 网络失败 | 不提前更新终态；保留筛选和未提交输入 | 用户手动重试 | T-08 |
| 部分成功 | 按逐项结果更新，不把整批标成失败或成功 | 失败项可手动重试 | T-04 或 T-06 |
| 系统异常 | 保留页面上下文并允许安全重试 | 仅幂等写可手动重试 | `系统异常，请稍后重试` |

### 6.3 导出契约

导出请求必须携带当前 Tab、完整筛选、字段白名单和脱敏策略；不得依赖前端只传一个 Tab 名称后由服务端使用不同筛选。导出不包含复选框、操作列、内部标识以外的技术调试字段、明文手机号或审计日志原文。

导出是同步下载还是异步任务、最大记录数、文件格式、文件名、结果入口、保留期、失败重试和过期处理均未核实，见 O-09。在这些事项关闭前，原型只能模拟提交反馈，不代表生产流程已定。

## 7. 异常、边界与降级

| 场景 | 页面表现 | 系统处理 | 恢复 |
|---|---|---|---|

## 11. 发布、灰度与回滚

### 11.1 上线门槛

1. O-03、O-04、O-05、O-06、O-08、O-09、O-10 必须在开发冻结前关闭；否则相关写操作或导出不得进入生产。
2. 必须完成主账号前后端双重保护、对象级越权、跨主体不串改和手机号脱敏测试。
3. 必须验证列表、摘要和导出使用同一筛选语义，且全部字段遵守字段白名单。
4. 必须完成审计回读，证明角色、启停、移除和导出均可追溯。

### 11.2 灰度与回滚原则

先向内部平台管理员开放只读能力，再按“详情与导出 -> 角色编辑 -> 启停 -> 移除”的风险顺序逐步开放写操作。具体灰度范围、观察周期和功能开关能力见 O-12。

若出现对象级越权、手机号明文泄露、主账号被禁用 / 移除、跨主体误操作或导出范围错配，应立即停止相关入口和写请求，保留审计记录并按事故流程处理。回滚不得通过删除审计或手工改库掩盖已发生操作；数据补偿方案由技术评审给出。
