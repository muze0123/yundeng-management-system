## 1. 需求概述

### 1.0.1 页面定位

团队列表是云登后台“用户管理”下的团队主体工作台，面向平台管理员和有团队管理权限的组织管理员，完成团队主体的查询、比较和基础维护。它承接用户列表中的团队主体关系数据，并把“进入团队”交给成员列表；不承担成员编辑、部门组织树、企业认证和角色权限配置。

页面价值是让管理员在同一业务视图内回答三个问题：团队是谁、团队有多少成员和资源、团队是否仍在活跃使用。停用团队会影响成员登录和资源操作，因此所有写操作必须二次鉴权、可审计、可恢复。

### 1.0.2 用户场景

| 场景 ID | 角色与触发 | 目标结果 |
|---|---|---|
| S-01 | 管理员从用户管理进入团队列表 | 默认展示全部授权团队的第一页和“团队识别”视图。 |
| S-02 | 管理员输入团队名、`team_id` 或 `company_id` 查询 | 条件生效，回到第 1 页，并保留当前 Tab。 |
| S-03 | 管理员切换业务 Tab | 表格列和摘要指标随视图切换；筛选条件和页码保持当前结果口径。 |
| S-04 | 管理员点击“进入团队” | 跳转成员列表，携带 `teamId`，成员列表保留团队范围。 |
| S-05 | 有编辑权限的管理员创建或编辑团队 | 抽屉完成字段校验后提交，成功关闭并刷新列表。 |
| S-06 | 管理员停用或启用团队 | 二次确认后切换状态；停用失败时保留原状态并提示重试。 |
| S-07 | 管理员筛选后导出当前 Tab | 创建异步导出任务，Toast 提供任务中心入口；不在本页伪造文件完成。 |
| S-08 | 无权限、列表加载失败或筛选无结果 | 展示明确状态、恢复动作和不改变原筛选的错误反馈。 |

### 1.0.3 边界条件汇总

| 编号 | 触发条件 | 系统规则 | 用户可见表现 |
|---|---|---|---|
| B-01 | 关键词为空 | 不限制关键词；查询仍可按其他条件执行。 | 展示默认结果。 |
| B-02 | 关键词超过 40 个字符 | 前端阻止继续输入，服务端再次校验。 | 输入框保持 40 字上限。 |
| B-03 | 团队处于停用状态 | 允许查看和编辑（按权限），不允许“进入团队”执行业务操作。 | “进入团队”置灰并显示原因 Tooltip。 |
| B-04 | 当前用户不是团队负责人且无管理权限 | 隐藏创建/编辑/启停按钮；直达接口返回 403 时保留列表。 | 显示“暂无团队管理权限”。 |
| B-05 | 目标团队是当前会话团队 | 不允许在未确认情况下停用当前团队。 | 确认弹窗提示先切换当前团队。 |
| B-06 | 停用团队仍有启用成员或运行资源 | 服务端可拒绝停用；前端不自行推断。 | 展示接口返回原因，状态不改变。 |
| B-07 | 查询结果为空 | 不把空结果当接口失败。 | 默认态显示“暂无团队数据”；有筛选时显示“未找到符合条件的团队”。 |
| B-08 | 网络、超时或并发版本冲突 | 写操作回滚本地状态；列表旧数据保留并标记需刷新。 | Toast 提示可行动原因，提供重试/刷新。 |
| B-09 | 导出任务创建成功但文件未生成 | 仅记录任务已提交。 | Toast 跳转任务中心查看进度。 |
| B-10 | 页码因筛选或删除超出总页数 | 服务端返回合法页码；前端自动回到最后一页。 | 分页统计与列表同步。 |

### 1.1 背景与问题

用户列表可以按“团队主体关系”查看用户所属团队，但不能直接比较团队规模、资源使用和活跃状态，也没有团队主体的基础维护入口。管理员因此需要在多个页面之间反复核对 `team_id/company_id`、成员数和最近活跃时间。团队列表将主体识别、成员资源和活跃经营拆成三个 Tab，保证每个视图字段围绕一个明确判断目标组织。

### 1.2 一句话目标与成功指标

**一句话目标**：让授权管理员在一个页面完成“定位团队 → 判断团队状态 → 进入成员管理或维护主体”的闭环。

| 指标 | 定义 | V1 目标 |
|---|---|---|
| 首次查询成功率 | 成功返回列表的查询请求 / 总查询请求 | ≥99% |
| 列表接口 P95 | 首屏团队列表接口响应时间 | ≤800ms |
| 进入团队成功率 | 成功打开成员列表的点击 / 有效点击 | ≥99% |
| 主体保护命中率 | 当前团队停用/越权写操作被拦截比例 | 100% |

### 1.3 用户、角色与任务（JTBD）

| 角色 | 准入条件 | 任务 | 权限级别 |
|---|---|---|---|
| 平台管理员 | 拥有 `team.read` | 查询授权范围内团队，进入成员列表，查看脱敏主体数据 | 读 |
| 团队管理员 | 拥有 `team.read/update` | 编辑团队名称、负责人和备注，启停被授权团队 | 读写 |
| 只读管理员 | 拥有 `team.read` | 只读查询、切换 Tab、分页 | 只读 |

### 1.4 范围与非目标

**本期范围**：团队业务 Tab、关键词/类型/状态/负责人筛选、摘要指标、团队表格、分页、创建团队、编辑团队、进入团队、启停确认、导出任务提示、空态/失败态、权限保护和交互标注。

**非目标**：企业实名认证、团队邀请、成员增删改、部门树、角色权限编辑、订单退款、真实短信验证、任务中心详情页和跨团队资源迁移。

### 1.5 前置约束与假设

1. 后端以 `team_id` 为唯一主体 ID；`company_id` 可作为历史业务主体编号展示，但不作为前端唯一键。
2. `memberCount`、`environmentCount`、`proxyCount` 和活跃指标由服务端聚合，前端不依据当前页数据自行计算全局口径。
3. 所有写接口携带幂等键和对象版本号；权限在服务端再次校验。
4. 原型使用脱敏 Mock 数据，不连接真实接口、不发送短信、不生成真实文件。
5. 团队负责人联系方式只展示脱敏值；导出明文需独立权限和审计。

## 2. 信息架构、入口与用户流程

### 2.1 入口与路由

| 入口 | 路由/文件 | 初始参数 | 返回行为 |
|---|---|---|---|
| 用户管理 / 团队列表 | `team-list` / `Prototype/团队列表.html` | `tab=identify`、`page=1` | 保留最近一次 Tab 和筛选条件（仅会话内）。 |
| 用户列表团队名/主体字段 | `Prototype/团队列表.html?teamId=` | `teamId` | 高亮并定位目标团队。 |
| 团队列表“进入团队” | `成员列表.html?teamId={teamId}` | 团队范围 | 成员列表按团队筛选；若页面不存在则由平台路由接管。 |
| 导出成功 Toast | `任务中心.html?tab=downloads&taskId=` | 任务 ID | 定位下载任务。 |

### 2.2 主流程

```text
进入团队列表
  → 读取权限、团队列表和摘要
  → 选择业务 Tab / 筛选条件
  → 查询（条件 AND，页码归 1）
  → 查看团队行或打开创建/编辑抽屉
  → 进入团队、导出或启停
  → 服务端鉴权与幂等
  → 成功刷新列表并 Toast；失败保留原状态并提供恢复
```

### 2.3 关键用户旅程

#### 2.3.1 查询并进入团队

1. 首次进入展示“团队识别”Tab 和第一页。
2. 输入团队名称、`team_id` 或 `company_id`，可叠加类型、状态和负责人条件。
3. 点击查询或按回车，列表刷新至第 1 页。
4. 点击“进入团队”，跳转成员列表并携带 `teamId`；停用团队不可进入。

#### 2.3.2 创建/编辑团队

1. 点击“创建团队”或行操作“编辑”。
2. 抽屉展示团队名称、类型、负责人、备注；编辑时预填当前数据。
3. 提交前执行必填、长度和唯一性校验；失败显示字段级错误，不关闭抽屉。
4. 成功关闭抽屉，刷新列表并提示结果。

#### 2.3.3 启停团队

1. 点击行操作中的“停用团队/启用团队”。
2. 停用必须确认影响范围；当前会话团队或有运行资源时由服务端最终判定。
3. 成功切换状态并刷新；失败恢复原状态并提示原因。

## 3. 页面与交互规格

### 3.0 页面整体结构

页面复用云登 App Shell：顶栏 56px、侧栏 220px/68px、主内容区唯一纵向滚动；业务内容采用设计系统规定的“筛选区 + 数据区”两块卡片。表格最小宽度 1180px，窄屏仅表格容器横向滚动。

```text
AppShell
├─ TopBar：面包屑、通知、账号
├─ Sidebar：用户管理 / 团队列表高亮
└─ Main
   ├─ FilterSection：视图 Tab、关键词、类型、状态、负责人、查询/重置
   └─ DataSection：摘要指标、团队表格、分页
GlobalLayer
├─ TeamEditorDrawer：创建/编辑
├─ ConfirmDialog：启停确认
└─ Portal Annotation Layer：交互说明
```

### 3.1 视图 Tab 与筛选区

| Tab | 业务问题 | 默认列 |
|---|---|---|
| 团队识别 | 这个团队是谁、由谁负责、是否可用 | 团队名称、团队 ID、类型、负责人、状态、创建时间 |
| 成员与资源 | 团队规模和资源使用量如何 | 团队名称、成员数、活跃成员、环境数、代理数、最近活跃 |
| 活跃与经营 | 团队是否持续使用、是否需要关注 | 团队名称、最近活跃、首单时间、累计消费、活跃等级、风险 |

筛选字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| 关键词 | 输入 | 模糊匹配团队名；完整 `team_id/company_id` 精确匹配；最多 40 字。 |
| 团队类型 | 单选 | 全部、个人团队、企业团队。 |
| 团队状态 | 单选 | 全部、正常、停用。 |
| 负责人 | 单选 | 仅展示授权范围内负责人。 |
| 创建时间 | 日期范围 | 可选；开始日期不得晚于结束日期。 |

筛选条件为 AND 关系。点击查询/按回车回到第 1 页；点击重置清空条件并恢复默认 Tab，不改变授权范围。

### 3.2 摘要指标

当前结果展示 4 个指标：团队总数、正常团队、总成员数、近 7 天活跃团队。指标跟随当前 Tab 和筛选条件刷新；无结果时显示 0 或“—”，不展示旧口径。

### 3.3 团队表格

固定第一列为团队名称和团队类型标记；数字、ID、时间使用等宽字体并左对齐。

| 字段 | 规则 |
|---|---|
| 团队名称 | 最多 40 字；点击名称打开团队信息抽屉；企业主账号团队显示“主团队”标记。 |
| 团队 ID / company_id | 展示 `team_id`，辅助显示历史 `company_id`；可复制，复制成功 Toast。 |
| 团队类型 | 个人团队/企业团队 Badge。 |
| 负责人 | 姓名 + 脱敏手机号；无负责人显示“待完善”。 |
| 成员数 | 服务端聚合总成员数；点击“进入团队”查看成员明细。 |
| 活跃成员 | 近 30 天有有效登录或成功启动的成员数。 |
| 环境数/代理数 | 服务端聚合，0 值显示 `0`。 |
| 最近活跃 | `YYYY-MM-DD HH:mm:ss`，无记录显示“—”。 |
| 状态 | 正常/停用 Badge。 |
| 操作 | 进入团队、编辑、启用/停用；无权限隐藏写操作。 |

### 3.4 分页与空态

- 默认每页 10 条，支持 10/20/50 条；显示页码、跳页、共 N 条、第 X/Y 页。
- 默认空态：“暂无团队数据”，提供“创建团队”（有权限时）。
- 筛选空态：“未找到符合条件的团队”，提供“清空筛选”。
- 加载失败保留上一次成功列表并显示“加载失败，点击重试”；首次加载失败显示整区失败态。

### 3.5 创建/编辑团队抽屉

抽屉宽 520px，右侧滑出，标题为“创建团队”或“编辑团队”。

| 字段 | 必填 | 校验 |
|---|---|---|
| 团队名称 | 是 | 1–40 字；同一授权范围内唯一。空值提示“请输入团队名称”；重复提示“团队名称已存在”。 |
| 团队类型 | 是 | 个人团队/企业团队；创建后不可修改。 |
| 负责人 | 是 | 从授权成员中单选；无负责人提示“请选择团队负责人”。 |
| 备注 | 否 | 最多 200 字，显示实时字数。 |

提交按钮在请求期间 loading 且防重复点击。创建成功提示“团队创建成功”；编辑成功提示“团队信息已更新”。关闭抽屉不保存；存在未保存修改时二次确认。

### 3.6 启用/停用确认

- 停用标题：“确认停用该团队吗？”；正文说明成员将无法进入团队，已有数据保留。
- 启用标题：“确认启用该团队吗？”；正文说明成员可恢复访问。
- 当前会话团队、服务端拒绝或权限变化时不改变 UI 状态。

### 3.7 导出

导出作用于当前 Tab 和全部筛选结果，不受当前页限制。确认文案：“本次将导出当前筛选条件下的全部团队数据，结果可在任务中心查看和下载。”成功只提示任务已提交；字段权限、脱敏、文件生命周期和审计由后端负责。

## 4. 权限、可见性与数据安全

| 权限 | 读取列表 | 查看敏感负责人信息 | 创建 | 编辑 | 启停 | 导出 |
|---|---:|---:|---:|---:|---:|---:|
| `team.read` | 是 | 否 | 否 | 否 | 否 | 否 |
| `team.read_sensitive` | 是 | 是 | 否 | 否 | 否 | 否 |
| `team.create` | 是 | 按字段权限 | 是 | 否 | 否 | 否 |
| `team.update` | 是 | 按字段权限 | 否 | 是 | 是 | 否 |
| `team.export` | 是 | 后端脱敏策略 | 否 | 否 | 否 | 是 |

前端隐藏/置灰只用于体验，所有接口必须服务端鉴权。负责人手机号默认脱敏；复制、导出和审计日志不得将明文写入埋点。

## 5. 数据模型、业务规则与状态机

### 5.1 领域对象

`Team`：`teamId`、`companyId`、`name`、`type`、`ownerId`、`ownerName`、`ownerPhoneMasked`、`status`、`memberCount`、`activeMemberCount`、`environmentCount`、`proxyCount`、`firstOrderAt`、`totalConsumeAmount`、`lastActiveAt`、`riskLevel`、`version`、`createdAt`、`updatedAt`。

### 5.2 状态机

```text
正常 --停用确认/服务端通过--> 停用
停用 --启用确认/服务端通过--> 正常
任一状态 --删除/解散--> V1 不提供
```

停用不是删除；历史成员、资源和经营数据保留。进入团队只允许 `正常` 状态。

### 5.3 业务规则清单

1. `teamId` 全局唯一，`name` 在授权范围内唯一。
2. 统计字段由服务端按固定时间窗口计算，页面不使用当前页推导总数。
3. 团队类型创建后不可修改；改变主体类型需走企业认证流程。
4. 当前会话团队不可直接停用，必须先切换到其他团队。
5. 所有写操作记录操作者、对象、旧值、新值、结果和失败原因。

### 5.4 并发、幂等与一致性

创建/编辑/启停请求携带 `Idempotency-Key`；编辑和启停携带 `version`。返回 `VERSION_CONFLICT` 时保留用户输入，提示刷新后重试；列表刷新不得覆盖未保存抽屉表单。

## 6. 接口与前后端契约

| 场景 | 接口 | 说明 |
|---|---|---|
| 团队列表 | `GET /api/v1/teams` | Tab、筛选、分页和摘要同一查询口径。 |
| 团队详情 | `GET /api/v1/teams/{teamId}` | 打开详情/编辑抽屉。 |
| 创建团队 | `POST /api/v1/teams` | 幂等；返回团队及版本。 |
| 更新团队 | `PATCH /api/v1/teams/{teamId}` | 乐观锁；团队类型不可修改。 |
| 启停团队 | `POST /api/v1/teams/{teamId}/status` | 服务端判定当前团队和资源约束。 |
| 导出任务 | `POST /api/v1/teams/export-tasks` | 返回 `taskId`，异步生成文件。 |

通用错误：`403` 无权限、`404` 团队不存在、`409` 版本冲突/名称重复、`422` 字段错误、`5xx` 服务异常。前端不展示内部堆栈和敏感字段。

## 7. 异常、边界与降级

| 场景 | 页面表现 | 恢复 |
|---|---|---|
| 首次加载失败 | 列表和摘要显示失败态 | 点击重试 |
| 查询失败 | 保留旧列表，顶部提示失败 | 修改条件或重试 |
| 权限被撤销 | 关闭写操作抽屉，保留只读列表 | 重新加载权限 |
| 名称重复 | 抽屉字段下方红字 | 修改名称后重试 |
| 网络断开 | 写按钮恢复可点 | 检查网络后重试 |
| 无结果 | 展示对应空态 | 清空筛选/创建团队 |

## 8. 配置、埋点、日志与监控

埋点事件：`team_list_view`、`team_tab_switch`、`team_search_submit`、`team_enter_click`、`team_create_result`、`team_update_result`、`team_status_change_result`、`team_export_submit`。埋点只传 `team_id` 哈希、结果和失败类型，不传团队名称、手机号或自由备注。

审计覆盖：创建、编辑、启用、停用、查看敏感负责人信息、复制和导出。监控列表接口 P95、403 比例、409 比例、写操作失败率和导出任务创建成功率。

## 9. 非功能性与技术约束

- 页面为单文件 HTML5 + Tailwind CDN + Lucide CDN + 原生 ES6 JavaScript；无需构建。
- 列表首屏目标 P95 ≤800ms；表格支持 1024px 以上横向滚动。
- 所有交互按钮可键盘聚焦；弹窗/抽屉支持 Escape 与遮罩关闭。
- Mock 数据不少于 8 条，覆盖正常、停用、待完善、高风险和多成员状态。
- 页面遵守 `design.md` 的颜色、字号、间距、圆角、表格、分页和 Portal 标注规范。
