# 数据总览 PRD

> 所属模块：数据埋点 / 数据总览  
> 路由：`/data-tracking/overview`  
> 优先级：P0  
> 依赖：《数据埋点PRD.md》《云登指纹浏览器数据埋点.md》  
> 状态：可直接用于 Vibecoding

## 1. Problem Statement

产品、运营和管理者无法在一个可信页面中同时判断核心使用、代理商业化、实名认证、环境运行和埋点质量。不同报表口径不一致、更新时间不透明、漏斗分母为零或数据未成熟时容易产生错误结论；单个图表故障还可能阻塞整页。

## 2. Solution

提供聚合数据总览：公共筛选、核心 KPI、产品趋势、实名认证漏斗、代理购后价值、环境质量、功能采用和数据质量摘要。每张卡片独立加载、独立失败并支持下钻；所有指标展示定义、更新时间和统计边界。

## 3. User Stories

1. 作为产品经理，我想查看 DAU、WAU、MAU、激活与 WSLE，以判断产品使用健康度。
2. 作为产品经理，我想对比当前周期与上一周期，以判断变化方向。
3. 作为产品经理，我想查看新用户激活漏斗，以定位 TTFV 阻塞。
4. 作为产品经理，我想按个人/企业查看实名漏斗，以比较认证效率。
5. 作为代理负责人，我想查看购买、绑定、检测、启动和有效运行，以判断购后价值。
6. 作为客户端负责人，我想按版本查看环境创建、启动与异常退出，以定位版本问题。
7. 作为数据负责人，我想查看到达率、完整率、重复率和延迟，以判断数据可信度。
8. 作为运营，我想查看授权团队范围内的聚合结果，而不能查看用户明细。
9. 作为用户，我想在单卡失败时继续查看其它数据。
10. 作为用户，我想知道数据更新时间和是否过期。

## 4. 页面结构

```text
FilterSection
├─ 日期范围 / 团队 / 客户端 / 版本
└─ 查询 / 重置 / 刷新
DataSection
├─ KPI Grid
├─ 产品核心趋势
├─ 新用户激活 + 实名认证漏斗
├─ 代理购后价值 + 环境质量
├─ 功能采用
└─ 数据质量摘要
```

≥1440px KPI 4 列、图表双列；1280–1439px 双列不变但缩减留白；1024–1279px KPI 2 列、图表单列。图表卡最小高 320px。图表必须提供“查看数据表”切换，不能只依赖视觉图形。

## 5. 筛选与组件

| 组件 | 规则 |
|---|---|
| 日期 | 默认最近 7 天；快捷项今日/昨日/7/30/90 天；最大 730 天 |
| 团队 | 按数据权限过滤；默认全部授权团队 |
| 客户端 | all/pc/web/server |
| 版本 | 依赖客户端；客户端变化后清除无效版本 |
| 刷新 | 保留筛选，重新生成 requestId；显示最后更新时间 |
| KPI | 数值、环比、单位、定义 Tooltip、下钻 |
| 图表 | 标题、图例、Tooltip、数据表、局部刷新、局部错误 |

KPI：DAU、WAU、MAU、激活用户、WSLE、代理购买成功用户、GMV、环境启动成功率、P0 事件到达率。数据清单未定义的派生指标必须标记“后台派生”，不得改写源埋点。

## 6. 交互与数据流

1. 进入页面并行请求权限/枚举、KPI、趋势、漏斗、环境和质量；各区块独立 requestId；
2. 全局筛选变化更新 `appState.globalFilters`，取消所有旧区块请求并重新查询；
3. 点击 KPI 将路由到分析中心，并写入 metricId、日期和分群参数；
4. 实名漏斗 personal/enterprise Tab 只刷新该卡片；Tab 选择写入 URL；
5. 点击代理服务商/失败码打开详情 Drawer；关闭后保持图表焦点；
6. 点击质量异常跳转质量告警并携带 eventName/problemType；
7. 查询失败时旧结果标记“数据可能已过期”，写操作与导出禁用；
8. “查看数据表”与图表共用同一结果，不发重复请求。

## 7. 指标与口径

| 指标/漏斗 | 口径 |
|---|---|
| WSLE | 周内成功启动且有效运行 ≥60 秒的去重环境数 |
| 激活用户 | 注册后 7 日内首次有效运行的用户 |
| TTFV | 注册成功到首次有效运行时长中位数/P75 |
| 实名漏斗 | 引导曝光→去认证→到达→提交→审核通过→任务恢复 |
| 代理首购 | 市场到达→商品→规格→实名→订单→支付→资产入账 |
| 购后价值 | 购买→绑定→检测→启动→有效运行→7 日再次运行 |
| 启动成功率 | launch_result=success ÷ launch_click，按 launch_request_id 去重 |

分母为 0 显示“—”；小于 0.01% 显示“<0.01%”；环比基期为 0 显示“不可比”。未完成周期标记“数据未完整”，不参与平均。

## 8. 状态与边界

| 状态 | 表现与恢复 |
|---|---|
| 首屏 Loading | 保持完整卡片骨架；10 秒超时转整页 Error |
| 局部 Loading | 仅目标卡片骨架，其他卡片可操作 |
| 默认 Empty | “当前时间范围暂无数据”，提供最近 30 天 |
| 筛选 Empty | “当前筛选条件下暂无数据”，提供清空筛选 |
| 局部 Error | 卡内显示原因与重试，不清空其它区块 |
| 整页 Error | 基础枚举/权限失败，提供重试和返回 |
| Forbidden | 显示缺少 `tracking.overview.read` |
| Extreme | 服务商 Top 9+其他；失败码 Top 10；大数缩写且可查看完整值 |

## 9. 权限与安全

查看权限为 `tracking.overview.read`；下钻分析需要 `tracking.analysis.read`；聚合导出需要 `tracking.aggregate.export`。服务端按团队范围裁剪数据。页面禁止展示用户直接身份、完整 IP、证件、Cookie、代理凭证和问题原文。

## 10. 接口契约

| 场景 | 接口 | 关键响应 |
|---|---|---|
| 枚举/权限 | `GET /api/v1/tracking/overview/context` | filters、permissions |
| KPI | `GET /api/v1/tracking/overview/kpis` | items、comparison、updatedAt |
| 趋势 | `GET /api/v1/tracking/overview/trends` | series、granularity |
| 漏斗 | `GET /api/v1/tracking/overview/funnels` | steps、counts、rates |
| 质量 | `GET /api/v1/tracking/overview/quality` | metrics、violations |

区块接口失败独立返回 requestId/code；前端只渲染匹配当前过滤快照的响应。

## 11. Mock 与标注

Mock 至少 9 张 KPI、3 组 30 日趋势、personal/enterprise 两组实名漏斗、5 个代理服务商、10 个失败码和 6 项质量指标。覆盖正常、0 值、分母 0、超大数、局部失败和未成熟周期。

Portal 标注至少覆盖：全局筛选、刷新、指标定义、KPI 下钻、实名类型切换、漏斗步骤、代理下钻、环境失败码、质量跳转和数据表切换。

## 12. Testing Decisions

通过 `appState.globalFilters + overviewSections` 测试可见行为；每张卡片是独立错误边界。验收：

1. 筛选联动和旧请求取消正确；
2. 个人/企业漏斗独立可切换；
3. 分母 0、未成熟周期和环比不可比显示正确；
4. 单卡失败不影响其它卡；
5. 下钻参数与当前筛选一致；
6. 图表与数据表数值一致；
7. 权限和敏感数据约束通过；
8. 三种目标宽度无布局破坏。

## 13. Out of Scope

自助配置总览卡片、用户明细、预测、自动归因、真实导出任务和业务系统写操作。
